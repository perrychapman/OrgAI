# OrgAI architecture

OrgAI is an Electron app built with electron-vite and three processes. The main process (src/main) holds the runtime adapters, run manager, connections and model catalog, MCP servers and secrets, usage tracking, setup service, worktrees and JSON stores. The preload (src/preload) exposes window.orgai. The renderer (src/renderer) uses React 19 with React Flow and zustand. IPC types live in src/shared/types.ts. Two provider adapters exist: Claude (Claude Agent SDK) and Codex (`codex app-server`). They are reached through three connections: Anthropic, OpenAI and LiteLLM.

The UI overhaul's shell pass and its parallel restyles have landed (docs/design/plan.md, spec.md). The shell is built on native elements with container queries: components/layout, components/ui primitives, top-level project tabs, and a theme layer driven by AppSettings.appearance. Radix Primitives and react-resizable-panels were not adopted (Role.skills has since landed through the skills runtime, #11). plan.md still lists them, so they remain a possible later step. Items below marked PLANNED do not exist in the code.

## Stack

- TypeScript (tsc 7, separate node and web tsconfigs, no baseUrl)
- Electron 45 + electron-vite 6 + Vite 8
- React 19, @xyflow/react 12 (React Flow), @dagrejs/dagre, zustand 5, react-markdown + remark-gfm
- lucide-react 1.64 (SVG icons that take their color from currentColor)
- Plain CSS with custom-property design tokens (no CSS framework)
- @anthropic-ai/claude-agent-sdk 0.3.312 (Claude adapter), zod 4 for harness tool schemas
- @openai/codex 0.166.0 (Codex adapter and the OpenAI connection: `codex app-server`, JSON-RPC over stdio)
- vitest 3 (node env) for unit tests; playwright-core Electron driver for e2e
- electron-builder (Windows nsis + portable tested; mac dmg and linux AppImage configured, untested)
- Node >= 22, git (worktree isolation)
- Not installed (plan.md keeps them as a possible later step): radix-ui, react-resizable-panels. The frontend-design skill is not vendored in .claude/skills.

## Modules

### Shared contracts

IPC-safe types (Project, Role, RunEvent, UsageStatus, connections, models, remaps, MCP servers, plugins, install requests, connectors, IPC names), the connector catalog (connectors.ts: CONNECTORS, CONNECTOR_REDIRECT_URI), defaults (adapterForProject, builtin models, tier helpers, MCP secret names), the built-in Architect and MCP assistant roles and setup tool names. RunSummary.endedWithApp is set by RunStore at startup for runs cut by the app quitting. Role.skills (skill ids) is in the contract; see the Skills bullet.

- Appearance: AppSettings.appearance (AppearanceSettings: theme 'dark' | 'light' | 'system', accent '#rrggbb', canvas { pattern dots/grid/none, tint, edges curved/orthogonal/straight, minimap }, reduceMotion 'system' | 'on'). defaults.ts holds DEFAULT_APPEARANCE (theme stays 'dark' until the light theme is signed off) and THEME_BACKGROUND (window background per resolved theme, matching --surface-0). Main applies the theme to nativeTheme.themeSource at startup and on every settings:set, then broadcasts settings:changed (IPC.settingsChanged, preload window.orgai.onSettingsChanged).
- Notifications: AppSettings.notifications is the single source of truth, and main reads it at every decision (notifications.ts). window.orgai.notifications.setEnabled (app:setNotifications) remains only as a deprecated mirror into it. The renderer no longer calls it.
- Projects: projects:checkPath returns ProjectPathCheck (exists, isDirectory, isGitRepo, suggestedName, empty) and never rejects. projects:create validates the path (ProjectStore createPathError) and throws a readable message. ProjectCreateInput.mock creates a project on the mock adapter (provider.id 'mock'). It is accepted only when the mock adapter is registered (ORGAI_MOCK=1).
- Cards: every *.resolved RunEvent (permission, proposal, question, rules, merge, mcpInstall) may carry `cancelled?: true`. src/main/runtime/pendingCards.ts cancelPending resolves every open card of a run as cancelled. RunManager calls it from emit when a run reaches an outcome or a paused status, and at teardown.
- Transcript: TranscriptEntry.source 'harness' marks entries the harness wrote (nudges, hand-offs, notices, limit notices). Claude, Codex and mock write them as system blocks with a one-line summary and a detail.
- Run titles: RunSummary.title (optional, at most RUN_TITLE_MAX_CHARS = 32 characters) is a short AI summary of a work run's first message, and RunEvent `{ type: 'run.title', runId, title }` announces it, at most once per run and possibly after the run ended. Both ride the existing runs:list / runs:get / runs:listLive and run-event paths, so no IPC or preload change was needed. It is absent until generated and stays absent when generation fails or is skipped. The UI falls back to the prompt.
- Agent import: projects:scanAgents(path) -> AgentImportScan (never rejects), projects:previewImport(AgentImportInput) -> AgentImportPreview (saves nothing), projects:applyImport(AgentImportApplyInput: AgentImportInput with a required digest) -> AgentImportApplyResult ({ project, previousRoles }; Undo = save previousRoles through projects:save), projects:exportOrg(projectId) -> OrgExportResult ({ path }). AgentImportInput is { projectId, sources?: AgentImportSource[], mode: 'replace' | 'merge', choices?: AgentImportChoice[], digest? }; a choice is { key, include, reportsTo? (slug or id), model? ('inherit', a catalog model or a tier name), action? 'add' | 'replace' | 'skip' } keyed by AgentImportItem.key (`<source>:<file>#<name>`, `~2` for repeats). Items carry model, originalModel, tier, modelReason (kept | tier | default | inherit | chosen), tools, toolsDropped, promptExcerpt (600 chars), promptLength, prompt (the whole prompt the role gets, at most 20,000 chars), elevatedTools (its tools among AGENT_IMPORT_ELEVATED_TOOLS Bash, Edit, Write, NotebookEdit, plus 'canSpawn'), action, replacesRoleId, slugConflict and notes. AgentImportPreview.digest (sha256 of the scanned definitions, responsibilities and color included) is required on apply, which refuses without it or when the folder changed since the preview. More than AGENT_IMPORT_MAX_CHOICES (200) choices are refused. ProjectCreateInput.importAgents starts a project with the imported roles ('replace'). ProjectPathCheck gains agentSources, instructionFiles and existingProjectId/existingProjectName (a project whose folder is the same by pathKey). ProjectProfile.agentDefinitions lists the agent locations present. AGENT_IMPORT_SOURCES / AGENT_IMPORT_SOURCE_LABELS: orgai, claude, opencode, codex, copilot, gemini, kiro, roo. defaults.ts importTierForModel classifies foreign model ids into tiers (tierForModel is unchanged except that it now ignores a `[1m]` suffix).
- Live runs and run windows: runs:listLive (every live run across projects), runs:pendingCards (PendingCards: a live run's open cards per kind, built by pendingCards.ts listPending over RunManager's PendingCardMaps) and window:openRun (FocusRunTarget, opens or focuses a run-scoped window; ids are checked with windowScope.ts isValidId plus store lookups).

- Usage and pricing (#10): ModelPrice is USD per token (inputPerToken, outputPerToken, optional cacheReadPerToken / cacheCreationPerToken; each finite, >= 0 and at most MODEL_PRICE_MAX_PER_TOKEN 0.01). AgentInstance.usage is AgentUsage (tokens input/output/cacheRead/cacheWrite, models: ModelUsageEntry[] with costUsd, priceSource and providerCostUsd, costUsd null = unknown, costSource provider/computed/unknown/none, costPartial, turns, toolCalls, retries, producedNothing, legacy). RunSummary.usage is RunUsage (the same cost fields plus models, roles: RoleUsage[], wallMs, agents, agentsWithoutResult, noResultTokens, nudges, waitingMs, limitHoldMs, idleMs, providerCostUsd, legacy, skills: SkillUseCount[], updatedAt) and RunEvent `run.usage` carries it. PriceSource: override, proxy, builtin, community, provider, unknown. `runs:usageStats` (UsageStatsQuery: projectId, since, until, kinds (default work), bucket day | week, limit default USAGE_STATS_DEFAULT_LIMIT 500, clamped 1..USAGE_STATS_MAX_LIMIT 2000) returns UsageStats (runs newest first, roles, trend: UsageTrendPoint[], totals, truncated); roles, trend and totals cover only the returned rows. `models:prices` (ModelPricesQuery { connection? }, an unknown connection throws) returns ModelPriceInfo[] (override, proxy and builtin rows; community prices are not listed). AppSettings.modelPrices (ModelPriceOverride[]: model, optional connection, price; at most MODEL_PRICE_OVERRIDES_MAX 200, normalized in store/settings.ts; a renderer save that leaves the field out keeps the stored list). Preload: window.orgai.runs.usageStats, window.orgai.models.prices.
- Skills (#11): Project.skills (SkillSpec[]: id, name, description, enabled, source user | repo | suggestion | library, repoPath, digest, files, addedAt/updatedAt, libraryId), Role.skills (granted SkillSpec ids; projects:save drops unknown ids and keeps the stored Project.skills), Project.skillEvaluation (SkillEvaluationSettings { enabled, tokenBudget }; DEFAULT_SKILL_EVALUATION off, 20,000, clamped 1,000..500,000). SkillLibraryEntry, SkillInfo (grantedTo, libraryMissing), SkillLibraryInfo (usedBy), SkillContent, SkillDraft, the import types (SkillImportItem keyed `<root>/<folder>`, SkillImportPreview with a digest, SkillImportApplyResult with undoId), SkillEvaluationReport / SkillFinding / SkillSuggestion, SkillUseCount and RunEvent `skill.used` { runId, agentId, skillId, name, at }. Limits: name 64 ([a-z0-9-], never "anthropic" or "claude"), description 1..1024 without < or >, body 100,000 chars, 50 files, 256 KB per file, 1 MB per skill, 100 skills per project or library. SKILL_REPO_ROOTS: .claude/skills, .agents/skills, .github/skills, .opencode/skills. SKILL_HARNESS_TOOLS list_skills / load_skill. Channels: skills:list / read / create / update / remove / linkLibrary / promote / previewImport / applyImport / undoImport / evaluate / lastEvaluation / applySuggestion, skillLibrary:list / read / create / addFromFolder / update / remove and the skillLibrary:changed push (preload window.orgai.skills, window.orgai.skillLibrary, onSkillLibraryChanged). ipc.ts checks ids first and refuses the harness project.

### Runtime core (provider-neutral)

- Adapter interfaces and the run manager. RunManager picks the adapter, resolves the connection and MCP servers per run, and handles approvals, proposals, questions, merges and MCP install cards.
- Harness tools, each with an audience: 'root', or 'spawners' for the MCP tools. Callers pass a HarnessToolCaller when they know the calling agent.
- Role prompts, activity strings, permission scopes, agent handles and messages, the continuation driver, WorktreeIntegrator and git worktree commit/merge.
- Vendor-neutral usage mapping.
- Image attachments. attachments.ts sanitizes untrusted pasted images: count and size limits, base64 checks, and magic-byte sniffing.
- Run end. activity.ts runOutcome maps how a run ended to finished, stopped or failed, and settleAgent relabels agents Finished, Stopped or Failed (TERMINAL_ACTIVITY). pendingCards.ts cancels the run's open cards at the same point.
- Agent tree rules. agentTree.ts resolves a reported agent's parent without creating cycles and repairs cyclic stored records.
- Concurrency. Any number of runs may be live at once, in one project and across projects, on every adapter: RunManager keys runs by id, ContinuationDriver and adapter sessions keep per-instance state, and each Codex session starts its own app-server. The only refusal is continueRun's "Session already open" for one provider session chain. RunManager.liveRuns() backs runs:listLive.
- Cross-run messaging. Work-run roots get list_runs and message_run (RUN_HARNESS_TOOLS). RunManager implements RuntimeContext.listRuns / messageRun and delivers through the target's RuntimeSession.receive(), which every adapter routes through its harness-message path (peerMessageText in prompts.ts frames the text as peer data). Delivery goes through the target's inbox: RunManager holds peer messages while the run waits on its user (see Conventions) and flushes them oldest first, one chained flush at a time. Both runs get a run.message event (direction out/in) and a root transcript system block ("Sent to run …" / "Queued for run …" / "Note from run …", marked TranscriptEntry.source 'harness').
- Run titles. RunManager.start fires src/main/ai/runTitle.ts generateRunTitle after the 'starting' status for every work run with prompt text. Setup-like runs, image-only prompts and the harness's auto-resume message (RESUME_TEXT, which carries the continued run's title) are skipped. The call is a one-shot RuntimeAdapter.complete with `kind: 'title'`, the run's RunConnection and the fast model from RunManagerOptions.fastModel (index.ts: ConnectionService.fastModel). It has a 20 s timeout and cleanTitle cleans the answer. The result is stored on the summary (index and record) and broadcast as run.title. A continuation passes the continued run's title, or a prompt excerpt, as context (`continues`). CompletionInput carries `kind` ('draft' | 'title') and `connection`: Claude merges `connection.env` (claude.ts completionEnv), Codex uses the connection instead of its completionConnection, and the mock answers 'title' with the first four words of the `<message>` text. Run titles are cancelled on user stop, project removal and app quit (`stopAll`); a run that ends on its own may still receive its title afterwards.
- Pricing (#10). pricing.ts is pure and vendor-neutral. RunManager prices every agent.upsert into a copy (priceAgentUsage) with a PricingContext read at each call (AppSettings.modelPrices, RunConnection.pricing or the catalog's ProviderModel.price, aliases from ANTHROPIC_DEFAULT_*_MODEL or tierModels, community prices unless AppSettings.communityPrices is false), so a saved override applies to a live run on its next usage update. Per model: override > provider-reported cost > 0 > proxy (LiteLLM /model/info) > builtin (BUILTIN_PRICES, per million tokens on the vendors' pricing pages read 2026-10-30, stored per token) > community > unknown (costUsd null, never 0). Every price passes sanitizeModelPrice (MODEL_PRICE_MAX_PER_TOKEN). priceFor matches exact, then normalized (prefix, date, `[1m]`), then version-suffix-only keys, through a per-record index and a 500-entry memo; builtinPrice matches the longest '-' prefix but never a codex/mini/nano/pro variant. listModelPrices backs models:prices.
- Run usage (#10). runUsage.ts holds the adapter helpers (emptyAgentUsage, setModelTokens with cumulative per-model totals, countUsage turns/toolCalls/retries), computeRunUsage, mergeCosts, normalizeRunRecord and buildUsageStats. The root agent never counts as producing nothing (agentProducedNothing in defaults.ts). RunManager drops an adapter's run.usage, recomputes RunUsage on agent.upsert, run.cost, run.status, plan.updated and skill.used, and publishes run.usage (with the index save) at most once per USAGE_THROTTLE_MS 1 s, trailing, or at once on a terminal status; an unchanged usage is not re-sent. summary.totalCostUsd follows usage.costUsd. The adapter's run.cost total feeds RunUsage.providerCostUsd only when RunConnection.pricing is unset (on LiteLLM it is a proxy estimate); a provider total wins when agent costs are provider-priced, unknown or none. Waiting, limit-hold and idle time come from IntervalTimers. Records saved before usage tracking are normalized on read (usageFromLegacyAgent, legacy: true; legacySummaryUsage when no record is readable).
- Skills in runs (#11). RunManager reads SkillService.forRun once at start for work runs (never setup-like or harness runs): enabled skills with at least one granted role, links whose entry is gone left out, as RunSkill (id, name, description, dir, files, roleIds) behind RuntimeContext.skills. A skill.used event for a skill the run does not have is dropped; at most RUN_SKILL_LOAD_LIMIT (1000) loads are counted; each counted load writes a harness transcript row "Loaded skill <name>" on the loading agent and feeds RunUsage.skills. harnessTools.ts list_skills / load_skill (audience all, left out when the adapter passes nativeSkills) answer only with the caller role's grants (an unresolved subagent gets none, only the root falls back to the root role), read regular files whose realpath stays in the skill folder (SKILL.md up to 256 KB, resource files 64 KB, binaries refused) and emit skill.used on a SKILL.md load. prompts.ts names the role's skills and the tool to load them with.
- Worktrees. worktrees.ts pathKey resolves the nearest existing ancestor's realpath (macOS /tmp is /private/tmp). withRepoLock serializes git work per checkout. Both commit-producing git calls (commit, merge) fall back to an OrgAI identity when git has none.

### Provider adapters

SDK event mapping and hook mechanics only. Only the Adapter Engineer edits claude.ts and mock.ts.

- Claude: the files below. Harness tools run in an in-process MCP server named "orgai". PreToolUse records which agent called them.
- Codex: codexAppServer.ts is the JSON-RPC client and binary lookup, codexProtocol.ts holds policies, launch config, dynamic tool specs and parsers, codexEvents.ts maps events, codexAgents.ts runs harness-side subagents as threads, and codex.ts is the adapter.
- mock.ts is the reference adapter. Its scripted MCP proposal uses a pinned package (mock-fs-server@1.0.0), so it passes validate.ts.
- Usage (#10): adapters only tally tokens per model (setModelTokens), turns, tool calls and retries, plus a provider cost where the provider reports one; RunManager prices. Mock markers: `[mock:no-price]` reports every agent on the unpriced model `mock-unpriced` (cost unknown), `[mock:computed-cost]` reports claude-sonnet-4-5 with no provider cost (builtin-priced), and the default script's silent report `mock-report-2` (UNPRICED_REPORT_ID) is unpriced and produces nothing.
- Skills (#11):
  - Claude (claudeSkills.ts): work runs with granted skills get a run-scoped local plugin in a temp dir, named `orgai-<8 random hex>` per run, holding `skills/<name>/`; each SKILL.md is re-emitted with name and description only, shell-injection bodies are refused, and files must be regular, unlinked, within 256 KB and inside the stored folder. Options: plugins (skipMcpDiscovery), options.skills = the qualified names (it only adds Skill(<name>) allow rules), settings.disableBundledSkills, env CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1 on work runs (set after isolateClaudeEnv), settings.disableSkillShellExecution on every run, settingSources ['project'] unchanged. Roles with a grant get the native Skill tool and their skills named in the prompt; AgentDefinition.skills is not set (it preloads content and grants nothing). The PreToolUse Skill gate (skillGate) runs before any rule or auto-allow and passes only `<plugin>:<name>` granted to the calling role (bare names, other plugins and repo skills are denied, with the granted names in the reason); skill.used is emitted from PostToolUse for that tool_use id. The plugin dir is removed at stop and teardown.
  - Codex: list_skills / load_skill as dynamic tools, and lockNativeSkills (codexProtocol.ts) per thread cwd: skills/list (forceReload) then skills/config/write { path, enabled: false } for each enabled native skill (at most 500), with `-c skills.bundled.enabled=false` and `skills.include_instructions=false`. It fails open: on an error it logs a run warning and the thread starts anyway (review M2). The role id is passed only when a thread resolves to a role.
  - mock.ts: list_skills / load_skill parity, roleId on harness calls, `kind: 'skills'` completions answer one deterministic suggestion, onUsage reported.

### Connections and model catalog

ConnectionService covers:

- probes and status, the OpenAI ChatGPT login (browser or device code) through Codex, and the LiteLLM key
- model discovery (Anthropic: the Claude adapter's listModels = SDK supportedModels() after init, no prompt; LiteLLM /v1/models and /model/info; Codex model/list with isDefault as ProviderModel.recommended), with the catalog and per-connection refreshedAt persisted to models.json (LiteLLM entries keep /model/info prices as ProviderModel.price). The anthropic catalog is the discovered list plus any builtin alias it omitted; OpenAI placeholders are only the cold-start fallback. Untrusted lists are capped (ids <= 200 printable chars, text <= 300, counts capped)
- the discovery schedule (startDiscovery: 20 s after boot, then an hourly check refreshing enabled, configured connections older than 24 h; one run at a time; a scheduled failure or empty result keeps the last good catalog, leaves the status alone and sets ConnectionInfo.modelsError). Every successful discovery broadcasts models.updated with changed and refreshedAt
- autoTiers: tier mappings OrgAI chose move forward to the catalog's suggestion (recommended first, on anthropic a floating bare alias first); a user's pick is kept while its model is in the catalog; connections:update drops a changed tier from autoTiers
- community prices (communityPrices.ts): LiteLLM's public model_prices_and_context_window.json fetched at most daily (redirect error, 20 s, 8 MB, sanitized, cached in <data>/model-prices.json), the last price fallback after the builtin table, off with AppSettings.communityPrices false and never in mock mode
- LiteLLM discovery caps (#10, litellm.ts): a response body over LITELLM_MAX_BODY_BYTES (5 MB) is refused, at most LITELLM_MAX_MODELS (2,000) models are kept, ids must pass validModelId (at most 200 printable chars, no whitespace, no leading '-'), and /model/info prices are sanitized (sanitizeModelPrice) before they become ProviderModel.price. ConnectionService.prices backs models:prices
- tier mapping and project remaps, including the projects:previewRemap dry run
- the per-run RunConnection (LiteLLM runs carry `pricing`), Codex plan usage and the LiteLLM key spend (probeLiteLLMUsage, /key/info)

- default connection at creation: prepareNewProject puts a new project on AppSettings.defaultConnection when creationConnection (defaults.ts) finds it usable and it maps every tier the roles use, else on anthropic (projects:create passes it to ProjectStore.create; mock and existing projects are untouched)

anthropicAuth.ts runs `claude --setting-sources project auth status` (the bundled CLI first, then PATH candidates) with the isolated child env in os.tmpdir(), so the status reflects what OrgAI's runs can use, and lists candidate claude binaries.

### MCP servers and plugins

McpService covers:

- persisting Project.mcpServers / Project.plugins, with secret values only in SecretStore
- the app-wide MCP library (store/mcpLibrary.ts, <data>/mcp-library.json): entries defined once, linked by projects (McpServerSpec.libraryId), snapshots refreshed on read, link / unlink / promote, library removal unlinks every project and drops Role.mcpServers grants
- OAuth for remote servers (oauth.ts: discovery, client registration with application_type 'native', PKCE, loopback redirect, RFC 9207 iss check before the exchange, token exchange and refresh); McpService.authorize / cancelAuthorize / revokeAuth / prepareForRun; resolve() injects the bearer
- resolving servers for runs and saving installs that the user approved with scope 'project'
- registry search (registry.ts, the official MCP Registry)
- the token-free server test (probe.ts: initialize + tools/list for stdio and streamable HTTP)
- spec validation (validate.ts: pinned versions, names, library entries) and the MCP assistant context and the virtual harness project (assist.ts)
- connectors (shared/connectors.ts catalog + mcp/connectors.ts + McpService.connectors*): curated presets for vendors' official remote MCP servers (41 entries, e.g. Google Workspace, Slack, Notion, Linear, GitHub, Stripe, Intercom, Supabase, DeepWiki, Exa, Cloudflare, Datadog, Asana, HubSpot, Box, PayPal, Microsoft Learn, AWS Knowledge, Context7, Granola, Neon, Amplitude, PostHog, Webflow, Miro, Zoom, Zapier, GitLab; a closing "Not yet" comment lists vendors left out and why; every oauthClient preset sets overrides.issuer; ConnectorDef.aliases are lowercase search words for connectorMatches; categories are CONNECTOR_CATEGORIES). `connectors:add({ connectorId, variant? })` (ipc.ts `connectorArgs` rebuilds it and connectors:setToken: kebab-case ids, a token of at most 4,000 chars or null) builds a library entry from the catalog only (url, transport, non-secret headers, secret header slot; McpLibraryEntry.connectorId / connectorVariant) and is idempotent per connector (switching a keyless entry to its key variant means removing it first); `connectors:list` returns ConnectorInfo (def, the entry's McpLibraryInfo, variant, state available / needsSetup / connected / error); `connectors:setToken` stores a 'token' connector's header with its prefix. Authorize, test, link, revoke and remove reuse the mcp:* / mcpLibrary:* channels. Auth kinds: 'none' (public server: no secret slot or OAuth, connected once added, mcp:authorize answers notRequired without a flow, setToken refuses), 'oauth' (DCR), 'oauthClient' (the user's own client id + secret; the flow listens on the fixed CONNECTOR_REDIRECT_URI `http://127.0.0.1:38917/callback`, which the user registers in the vendor console, and fails clearly when another program holds the port instead of moving to another port; one fixed-port sign-in at a time: a newer one aborts the pending one, which resolves 'error' "Authorization was cancelled: another sign-in started.", and listens once the port is released), 'token'. mcp:authorize refuses a client id or secret with control characters or over 512 / 4,000 chars; a pasted token header must be printable ASCII. Presets may supply OAuth endpoints ('replace' skips discovery; 'fallback' after a failed one, and discovered endpoints off the preset endpoint's registrable domain, the last two host labels, are replaced by the preset's so a client secret never leaves it), scopes, extra authorization parameters (reserved ones ignored), no `resource` parameter, and Slack's `authed_user` token shape (oauth.ts OAuthPreset). connectorEase(def, variantId?) maps auth kinds to 'none' | 'signIn' | 'token' | 'ownApp' (EASE_ORDER, easeRank: none first) and each defaultVariant is the easiest variant. McpLibraryEntry.connectedAt (epoch ms) is main-only: set on a connector's authorize success, token set, or add of a 'none' preset; cleared by revokeAuth, a null token or losing the connector; never copied into linked specs; ConnectorInfo.connectedAt carries it while the card is connected. Under ORGAI_MOCK=1 only (McpService `mock`), connector entries authorize (account mock@example.com, a stand-in token never used outside mock mode; no placeholder client id is stored, and a legacy 'mock-client' id never passes the real preflight) and test (fake tools) without network. Every preset has `verified: false`.

### Skills (#11)

SkillService (service.ts) covers:

- project skills: specs in Project.skills, files in `<data>/project-skills/<projectId>/<skillId>/`; create (from a SkillDraft: SKILL.md = name + JSON-quoted description + body), update (a draft keeps the resource files; on a link only enabled and roleIds), remove (returns the roles that lost the grant), grants by Role.skills. Deleting a project removes its skill files.
- the app-wide library: index `<data>/skill-library.json` (store/skillLibrary.ts), files `<data>/skills/<entryId>/`; create, add from a folder, update, remove (deletes every project's link to it and those grants), promote (copies a project-only skill into the library and relinks it under the same id, grants kept). A project skill with libraryId is a link whose snapshot (name, description, digest, files, updatedAt) is refreshed from the entry on every read (list, withLibrary, forRun); a link whose entry is gone is kept, flagged libraryMissing and never passed to runs. Every library change broadcasts skillLibrary:changed.
- the repo import (scan.ts): SKILL_REPO_ROOTS in order, `<root>/<name>/SKILL.md` folders, at most 100 candidates, folder depth 4. A repo import is a snapshot copy; the repository is never written. Each item carries `digest` (the files OrgAI stores, SKILL.md rewritten) and `sourceDigest` (the folder as found); the preview digest binds every candidate's repoPath and sourceDigest (and invalid reasons and warnings), and apply re-scans and refuses a missing or stale digest. An item matching an existing skill's repoPath (or name) with the same digest is 'unchanged', otherwise 'update'; a name taken by another skill refuses 'add'; a later root's duplicate name defaults to 'skip'. Apply backs up updated folders and grants; skills:undoImport restores skills, files and grants (one undo per project, expired by the next skill mutation and at quit).
- evaluation (evaluation.ts, evaluate.ts, suggest.ts): deterministic checks over the newest SKILL_EVALUATION_RUNS (20) work runs (neverLoaded, neverGranted, overlap by token-set similarity, vagueDescription, stale repo paths probed with confinedPathExists (no contents read, never outside the project), libraryMissing, repeatedToolSequence, repeatedCorrection). The model step (a one-shot completion, `kind: 'skills'`, everyday tier, 60 s timeout, at most SKILL_MAX_SUGGESTIONS 3 drafts) runs only when Project.skillEvaluation.enabled, there are gap findings and the token estimate fits tokenBudget; the report says why it was skipped ('disabled', 'no-gaps', 'budget', 'error'). Evidence (titles, details, paths, sequences) is redacted (bearer, key-like and 32+ char tokens) before the prompt and before saving. The report persists at `<data>/skill-evaluations/<projectId>.json`. A suggestion becomes a skill only through skills:applySuggestion. No A/B replay (re-running a task with and without a skill) is built.

Repo and picked folders are untrusted (files.ts, scan.ts, skillMd.ts): only name and description of the frontmatter are kept (other keys such as allowed-tools, hooks or model are dropped with a note), a body with Claude Code shell injection (!`cmd` or a ```! fence) is refused, UNC and device paths (two leading slashes) are never touched, symlinks and .git are skipped, every count and size is capped, nothing is executed and script-looking files are flagged. skillLibrary:addFromFolder accepts only a path the user chose in the main-process folder dialog in this session (ipc.ts wasPickedFolder, the last 20 projects:pickDirectory results).

### Capabilities (Team assistant)

CapabilityService (`src/main/capabilities/service.ts`, interface `CapabilityServiceApi` in types.ts) backs the capabilities:* channels. ipc.ts rebuilds every input field by field (`capabilityArgs`: SAFE_ID ids, a 64-hex digest, at most 100 role ids, access 'read' | 'full' or omitted, the harness project refused) so the renderer can never pass a path, a spec or file content.

- discover: token-free reads in a fixed order, each a step that can be cancelled between sources (`capabilities:cancel`, the result comes back `partial` with 'Stopped.' sources): this project (`sources.ts`), repo skills and MCP configs (`localSkills.ts`, `localMcp.ts`, `paths.ts`: .mcp.json, .cursor/mcp.json, .vscode/mcp.json), other tools' skill folders and MCP configs on this computer (Claude Code, Claude Desktop, Cursor, Codex, ~/.agents, Copilot, Claude Code plugins), the MCP and skill libraries, the curated connectors, and only with includeOutside the MCP Registry and the allowlisted `anthropics/skills` repo (`outside.ts`, unauthenticated GitHub contents API, SKILL.md only). A throwing source becomes an error row plus a warning; the rest continue. Items are merged, project duplicates dropped, cross-matched to the project (`inProject`), capped at CAPABILITY_MAX_ITEMS and bound by a sha256 `digest` (per item: id, kind, target, blockedReason and its binding: a local or registry MCP server's `mcpSpecDigest` of the spec apply would save (transport, command, args, url, env and header names with registry non-secret values, secretEnv, secretHeaders), a skill's file digest, else the target). An MCP item's `target` is the whole command (`command arg ...`, args with whitespace or quotes JSON-quoted) or URL, never truncated: over 400 chars (MCP_TARGET_MAX) or with control, zero-width or bidi characters the item is blocked ('Command too long to review'; `sanitize.ts` `reviewTarget`). Registry remotes must be https and not a private-IP literal (`isPrivateHost`) and their spec.url is stored scrubbed; GitHub skill folder names must start with a letter or digit. The payloads (folder paths, sanitized specs, fetched SKILL.md text) stay in main in a per-project snapshot (SNAPSHOTS_PER_PROJECT, with a global cap); skill folders keep only dir, real root and source digest and are re-read at apply.
- recommend: one-shot completion (`kind: 'recommend'`, everyday tier, CAPABILITY_RECOMMEND_TIMEOUT_MS, the request's AbortSignal) through RunManager.completeForProject, never a run. `recommend.ts` builds the prompt with every untrusted string as a single-line `key=value` field inside `<roles>` / `<candidates>` and parses strictly: unknown candidate or role ids dropped, at most 12 recommendations and 8 gaps, text clamped to 300 chars, 'full' downgraded to 'read' unless every role has a CAPABILITY_WRITE_TOOLS tool, blocked candidates never recommended. On error, timeout, cancel, no candidates or an unreadable answer it falls back to deterministic keyword matching (`fallbackReason`).
- apply / undo: apply takes `digest` plus a recommendationId (from the in-memory snapshot or the persisted review) and/or a candidateId, re-discovers when the snapshot is gone and refuses when the digest no longer matches. Grants go only to the chosen roles (Role ids in the contract, role slugs in McpServerSpec.roles). Skills become snapshot copies through SkillService.addSnapshot (home-folder skills skip dotfiles, .env*, *.pem, *.key with a note); a local or registry MCP server becomes a project server with secret slot names only, saved enabled: false while a secret is missing (needsSetup lists it); a connector is added to the library (read-only variant for 'read') and linked. One undo per project restores Role.skills, Role.mcpServers and server roles and removes what the apply added. After an apply the persisted review is re-bound by a refresh discovery that takes at most one snapshot slot per project (`Snapshot.refresh`; a refresh with the digest of a held snapshot inherits its recommendations and stays pinned), so applying any number of recommendations from one recommend result never evicts that result. There is no per-role grant channel (capabilities:setGrant was removed unused); grants otherwise change through projects:save.
- review (phase 2): `capabilities:review` (manual Re-check, or 'opened', throttled by TEAM_REVIEW_OPEN_THROTTLE_MS unless the project or a work run changed since) and `runEnded` (index.ts, work runs only, debounced RUN_ENDED_DEBOUNCE_MS). It re-discovers (never outside on automatic triggers), collects redacted run evidence (`evidence.ts`, newest 20 work runs), keeps still-useful pending recommendations, and runs the model step only when Project.teamReview allows (DEFAULT_TEAM_REVIEW auto 'ai', everyRuns, tokenBudget, new evidence or new candidates; otherwise `modelSkipped` says why). Dismissals are remembered by candidate fingerprint (digest, version, target). `capabilities:dismiss` takes a recommendationId and/or a candidateId: the recommendation comes from the persisted review or a recommend result still held in memory, the candidate from the review's discovery or a held snapshot; with no review yet a stub review (nothing pending, bound to that discovery, checkedAt = its createdAt) is written to hold the dismissal. Reviews persist at `<data>/team-reviews/<projectId>.json` (`reviewStore.ts`, shape-checked on read; plain JSON at rest holding secret-free discovery items and redacted evidence strings, text only, never secret values) and `capabilities:reviewUpdated` pushes the summary. Under ORGAI_MOCK=1 the automatic review fills recommendations from the keyword fallback without calling the model ('mockFree'), so the badge shows after the first finished mock run.
- Proactive model data classes: an automatic review's model step (`TeamReview.modelInput: 'proactive'`) gets repo and catalog items in full, library and project items with descriptions but an MCP target redacted like a local one (package-like args only), and local-machine items (origin 'local') only as kind, name and a redacted target, never their descriptions or paths. The manual Re-check and capabilities:recommend send every item (`'full'`).
- ORGAI_MOCK=1: index.ts seeds `<data>/mock-home` (`mockHome.ts`) and passes it as the home dir with an empty env, and outside fetches are fixtures, so mock discovery never reads the real home or the network.

## Conventions

- Keep `npm run typecheck` clean for both tsconfigs. Paths are ./-relative with aliases @shared and @renderer. Never add baseUrl.
- Every type that crosses IPC is defined in src/shared/types.ts and must be structured-clone safe. Wire new IPC in this order: shared types, main/ipc.ts, preload/index.ts and index.d.ts, then the renderer.
- The renderer only consumes normalized RunEvents and ConnectionEvents. Vendor SDK details never leave runtime/<provider>*.ts.
- Adapters contain only event mapping and hook mechanics. Shared behaviour goes in harnessTools.ts, prompts.ts, activity.ts, integration.ts, permissionRules.ts, ruleMatch.ts, network.ts, continuation.ts or usage.ts, and mock.ts is updated to match.
- Connections and adapters are separate. The connections are anthropic, openai and litellm, and the adapters are claude and codex.
  - Anthropic always runs on Claude and OpenAI always on Codex.
  - On LiteLLM the root role's model family picks the adapter (adapterForProject).
  - A work run whose roles mix families is refused before the run exists.
- Usage and cost per connection: usage.status reports carry `connection` (anthropic plan windows, openai Codex windows, litellm `spend` from `/key/info`); the renderer keeps the latest per connection. `RunSummary.connection` labels each run's cost. Run cost is host-priced (#10): RunManager prices every agent through pricing.ts (override > provider-reported > proxy `/model/info` > builtin > community > unknown) and RunUsage rolls it up; adapters never decide a final cost. A model with tokens and no price is unknown (null), never $0, and a partly priced total is a lower bound (costPartial). The LiteLLM endpoints and price fields are unverified against a live proxy.
- Remaps:
  - Role.tier plus each connection's tierModels drive remaps. A remap never clobbers an explicit pick of a valid catalog model, except when the project switches connection.
  - Remaps are reported as projects.remapped with Undo in the UI.
  - projects:previewRemap is the main-process dry run.
- Secrets live only in SecretStore (Electron safeStorage). Covered secrets: the LiteLLM key, MCP env and header values, and MCP OAuth client secrets and tokens.
  - Key scheme: project servers `mcp:<projectId>:<serverId>:{env|header|oauth}:<name>`, library entries `mcplib:<entryId>:...` (helpers in store/secrets.ts). A linked project server uses its entry's secrets.
  - McpOAuthConfig (endpoints, client id, expiry) is written by the main process only; mcp:upsert and mcpLibrary:upsert keep the stored value, and a url change drops it and its tokens.
  - They never cross IPC. Write-only inputs are allowed, and responses carry has-flags only.
  - They are never logged and are redacted from probe output. An API key reaches Codex only through the environment.
- projects:save (ProjectStore.saveFromRenderer) keeps the stored mcpServers and plugins. Those change only through mcp:* and plugins:*, approved setup or MCP proposals, and installs approved with scope 'project'. Deleting a project deletes its MCP secrets.
- OrgAI's Codex home is <data>/codex, so it never loads the user's ~/.codex config. CodexAppServer.start creates CODEX_HOME (recursive, mode 0o700) before spawning, since codex 0.166.0 exits 1 when it is missing (issue #8). An app-server exit error (codexExitMessage) appends a redacted stderr tail: the last 10 non-empty lines, at most 2,000 chars, with exact env secret values redacted and key-like tokens masked (maskKeyLike).
- Built-in roles (setup Architect, MCP assistant) take their model from AppSettings.setupModel / mcpAssistModel (default 'deep', a ModelSetting: a tier name or a concrete id; a saved old default 'opus' loads as 'deep'; normalized in store/settings.ts) through runtime/builtinModel.ts resolveBuiltinModel; RunManager logs a fallback warning once per run.
- The Claude child env is isolated (childEnv.ts isolateClaudeEnv). The Anthropic connection uses only the Claude Code login, CLAUDE_CODE_OAUTH_TOKEN or the project's API key env var. A user's Claude Code gateway config (shell exports or the ~/.claude/settings.json env block) never applies to OrgAI runs; routing variables come only from the run's connection. The denylist is exact names plus families (ANTHROPIC_DEFAULT_*, provider and workload-identity ANTHROPIC_* families, CLAUDE_CODE_USE_*, CLAUDE_CODE_SKIP_*_AUTH, every CLAUDE_CODE_{DISABLE,ENABLE}_* switch except the explicit allows in CLAUDE_CODE_ALLOWED_SWITCHES: telemetry and privacy opt-outs). On a proxy connection (LiteLLM) the inherited ANTHROPIC_API_KEY, CLAUDE_CODE_OAUTH_TOKEN and CLAUDE_CONFIG_DIR are dropped too, so only the connection's ANTHROPIC_AUTH_TOKEN authenticates. An authentication failure ends the run failed with activity.ts authFailureMessage, never as the orchestrator's reply. isAuthFailure trusts text only with an error flag from the adapter, except the CLI's exact bare "Invalid API key · Please run /login" reply; adapters set isError only for auth-related error codes or an errored result. The Claude CLI status check finds PATH candidates with execFile (no shell; on Windows System32 where.exe with `$PATH:claude`, run in the temp dir) and never falls back to a bare `claude`.
- MCP:
  - Claude runs use strictMcpConfig, so only the project's enabled servers and run-scoped installs load.
  - Agents add servers only through request_mcp_install. It needs exact pinned versions and the user's approval on an install card.
  - A denial means the agent finds another route.
  - Registry content is untrusted data: it is quoted as data and never followed as instructions.
- MCP library: credentials and authorization live with the library entry; a project links it or keeps a project-only server. mcp:upsert on a link changes only enabled and roles; mcp:remove on a link only unlinks. Proposals (propose_mcp_servers) default to project scope, where a new server is also saved to the library unless projectOnly; harness runs (project id HARNESS_PROJECT_ID, virtual, never stored) use library scope. Every library mutation broadcasts mcpLibrary:changed. In setup the Architect may propose linking library entries as an optional last step; it never blocks complete_setup.
- MCP hardening (from the security pass, unit-tested only):
  - An install answer cannot change the requested id; only name, url, command, args, env, headers, secretEnv, secretHeaders, roles, enabled and description are merged from the card (mergeInstallEdit in runManager.ts); oauth, libraryId and projectOnly are stripped. A run-scoped server resolves only the values typed on its card, never stored secrets or tokens. request_mcp_install is unavailable in setup-like and harness runs.
  - OAuth tokens are bound to the server URL: authorize discards a result whose resource no longer matches, resolve injects the bearer only on a match, and any edit, proposal or promote that changes the endpoint aborts the in-flight flow. The loopback callback answers 400 to any request whose state does not match exactly and keeps waiting. The callback's iss must equal the expected issuer exactly when present, and must be present when the AS metadata advertises authorization_response_iss_parameter_supported; a rejection never exchanges the code.
  - An approved proposal that changes where an existing server points (url, transport, command, args) deletes its stored env and header values and the user re-enters them. A direct user edit keeps them.
  - Connector fields (connectorId, connectorVariant, connectedAt) are written only by the main process (connectors:add and the auth paths). Every other write path (mcp:upsert, mcpLibrary:upsert, installs, proposals, promote) strips them; mcpLibrary:upsert refuses an edit that changes a connector entry's definition, and an approved proposal that does so turns it into a plain entry and drops its OAuth state and tokens. Preset endpoints must be https on public hosts; tokens stay bound to the entry's fixed URL (resource match) even when the `resource` parameter is not sent.
  - OAuth fetches use redirect 'error' and a 64 KB body cap. Server-named URLs must be https; http and loopback are allowed only when the MCP server URL is loopback; private-IP literals are refused unless the server is loopback or the URL is on the server's own origin (literal check only, no DNS lookup). A stored client and its secret are reused only for the same authorizationServer.
  - Server and project ids match SAFE_ID (/^[A-Za-z0-9_-]{1,128}$/, defaults.ts). projects:save refuses unknown, unsafe and harness ids; projects are created only through projects:create. Secret-kind inputs accept only env or header.
  - The harness project's cwd is <data>/harness-workspace (empty), not the data dir. Hidden-context data goes through promptDatum (assist.ts): one line, length-capped, < and > replaced.
- A project folder is untrusted content. The agent importer reads only regular files whose realpath stays inside the project root (escaping symlinks and junctions are skipped), never spawns a process or touches the network, and caps everything: 40 agents (also per file, before any referenced prompt is read), 20,000 prompt characters, 256 KB per file (read through one descriptor), 200 files including referenced prompts (.md, .txt or .prompt only, never under .git, read once each), 5,000 directory entries, 200 choices. Paths must be absolute, and a realpath with a .git segment is never read. The YAML subset cuts lines over 4,000 characters (with a warning) and never number-tests a scalar over 64 characters; its number regex has no ambiguous digit split, so no parser regex backtracks super-linearly (timing test in frontmatter.test.ts); a run of blank lines is skipped in one step, and the TOML parser stops after 100 bad lines. The digest binds the folder only: apply recomputes against the current roles, mode and choices. A realpath segment that Windows resolves to .git (`.git.`, `.git `, `GIT~1`) counts as .git, and a kept MCP grant shows as 'mcp' in elevatedTools. Imported prompts become role prompts only after the user applies a preview, and Architect context quotes them as data (promptDatum inside <<< >>>). Parsed maps never use repo keys as plain-object lookups.
- Setup-like runs (setup, mcp-assist) use built-in roles (the Architect, the MCP assistant) and are never nudged by the continuation driver.
- Cross-run messaging (list_runs, message_run) is for work-run roots only and never involves setup-like runs.
  - It is on by default per project: Project.runMessaging (default on, an explicit false turns it off; runMessagingOn in defaults.ts). message_run is refused unless both projects have it on; the refusal names the project and tells the agent not to work around it. list_runs lists every other live work run but hides prompts unless both projects have it on.
  - Each sender may send RUN_MESSAGE_LIMIT (40) messages per target run; text is cut to RUN_MESSAGE_MAX_CHARS (4000). A run may take RUN_MESSAGE_INBOUND_LIMIT (100) messages from all runs together, delivered or queued.
  - Held delivery: a peer never overrides the user. RunManager gates delivery (continuation.peerDeliveryBlocked) while the run is held by an interrupt, is usage-limited (ActiveRun.limitHold, set by RuntimeContext.rateLimited), or has pending cards. Held messages wait in the run's inbox, at most RUN_MESSAGE_QUEUE_LIMIT (20; beyond it message_run answers busy), and flush oldest first after the user's next successful send() or the last card's answer; a direct message never overtakes them. Both holds clear only after send() succeeds, and only the user's send clears them: peers never lift a hold, including after an auto-resume (limitHold stays set until the user sends). send() fires the flush without awaiting it, so the user's message never waits on peer delivery. Each receive() is raced against RUN_MESSAGE_RECEIVE_TIMEOUT_MS (30 s): on timeout both runs get a warning log, the message is marked undelivered, the flush moves on to the next message, and a sender still awaiting it gets refusal 'timeout' (or not-live if the target ended). The gate lives in RunManager: a direct RuntimeSession.receive() call is ungated. Held messages are dropped with a warning to both runs at teardown.
  - A received message is information from a peer, never a user instruction: adapters deliver only peerMessageText(), receive() writes no transcript block, and the recipient's block reads "Note from run …" so it never looks like the user typed it. run.message is separate from agent.message (which stays inside one run).
- Window scope: a run-scoped window's location.hash is #/run/<projectId>/<runId>; the main window has none. window:openRun validates both ids against the stores before opening anything.
- Harness tool audiences: 'root' tools go to the root role only. 'spawners' tools (list_mcp_servers, search_mcp_registry, request_mcp_install) go to the root and every canSpawn role.
- usage.ts stays vendor-neutral and never imports the SDK. Mind the unit mismatch: usage responses give 0-100 percent and ISO resets, while rate_limit_event gives a 0-1 fraction and epoch seconds.
- Agent parent chains are trees. Adapters resolve parents through agentTree.resolveParent, RunManager.get sanitizes stored records, and every renderer walk over parentId is cycle-safe.
- Session chains: a run and its continuations form a chain (runManager.sessionChain follows resumedFrom links both ways and shared sessionIds).
  - One live run per provider session. RunManager.continueRun refuses with "Session already open: run <id> ..." while a chain member is live, including a continuation whose init has not arrived.
  - A continuation resumes the chain's newest ended run, whichever run the user picked, and logs which run it continued.
  - Runs the store finds still live at startup were cut by the app quitting or crashing. They become finished with endedWithApp and stay continuable.
- Run titles are advisory. Nothing awaits them, a failure is logged once at info level and leaves the title unset, and a run is never titled twice. The one-shot completion uses the connection's fast tier: tierModels.fast, else the catalog's suggestion for the nearest tier (modelForTier) when it runs on the run's adapter, else the adapter's default (no model literal). The user's message is sent as `<message>` data and never as instructions.
- Git operations on one checkout are serialized through worktrees.withRepoLock (keyed by pathKey of the merge target). integrateWorktree, commitLeftovers, discardWorktree and prepareRepo take it; a merge review waits outside the lock, and different checkouts never block each other.
- SDK spawns go through the adapter's EXECUTABLE_OPTION, and the native CLIs stay in asarUnpack.
- Renderer layout goes through components/layout and components/ui. Responsive behaviour comes from container queries (container-type on layout regions).
- Skills (#11): Role.skills grants are enforced per agent by the harness (Claude: the PreToolUse Skill gate over the run-scoped `orgai-<hex>` plugin; Codex and mock: list_skills / load_skill answer only with the caller role's grants). AgentDefinition.skills is deliberately not used. Skill specs change only through skills:* and skillLibrary:* (projects:save keeps the stored Project.skills). Repo and picked skill folders are untrusted: OrgAI stores and re-emits SKILL.md with name and description only, refuses shell-injection bodies and UNC/device paths, and never executes anything from them. Setup-like and harness runs get no skills. A grant is not a confidentiality boundary (review M5): it decides what the harness offers and loads, while the files sit in the data dir and, on Claude, the run's temp plugin dir, which any agent with Read or Bash can open. Skill evaluation spends tokens only when the project enables it and within its token budget.
- Capabilities (Team assistant): other tools' config files and skill folders on the user's machine, the repo, the MCP Registry and GitHub are untrusted data. They are read with size caps, realpath confinement and no symlinks; nothing found is ever spawned, executed or connected to during discovery. An MCP candidate's review target is the exact command or URL that apply saves, never truncated (over 400 chars it is blocked), and the discovery digest binds the whole spec. Env and header values are never read into a candidate (secret names only); args carrying credentials (key-like values, URL userinfo, bearer/basic/token values, authorization headers, --header/-H/--auth/--bearer values) are dropped with a note and URLs lose their query and long mixed id segments. Outside candidates apply only when pinned (registry version, skill digest). Every grant is least privilege: the chosen roles only, 'read' by default. The proactive (automatic) model step never sends local-machine items' descriptions or paths. Mock mode uses `<data>/mock-home`, never the real home.
- Styling uses design tokens only. Never hardcode hex colors, shadows, radii, font sizes or z-indexes. Every token is defined for both dark and light themes.
- Hierarchy comes from the type scale, weight and spacing, not from uppercase micro-labels. Labels use sentence case, with at most one primary action per region.
- Nothing floats over the React Flow canvas except React Flow's own controls. Decision cards live in CanvasFrame's FrameTray. Banners and notices sit in layout regions.
- No div or span with onClick and no native confirm(): ask through ConfirmDialog / useConfirm. Every control is reachable by keyboard with a visible :focus-visible ring, and every IconButton gets a label.
- One status vocabulary: run status words come from lib/runStatus.ts, and agent end labels from activity.ts TERMINAL_ACTIVITY. Views do not invent synonyms.
- A fresh renderer (a second window or a reload) seeds a live run's decision cards from `runs:pendingCards` and then follows the `*.request`/`*.resolved` events. As of 3cde179 the main side and preload exist but no renderer code calls it yet (UX N2 stays open until it does).
- Harness-written transcript entries (source 'harness') render as quiet system rows with the detail behind a disclosure, never as user or model messages.
- Appearance is consumed through the <html> attributes and CSS vars that lib/theme.ts sets. Views never read AppSettings.appearance to style themselves.
- Icons are lucide-react via the Icon wrapper. No Unicode glyphs as icons.
- Motion respects prefers-reduced-motion.
- Unit tests are *.test.ts files beside the module they test. They run with vitest in the node environment and never spend tokens.
- Smoke scripts and the e2e scripts setup, history and worktree spend real tokens. Run them only with explicit approval. e2e:free (layout, runs, maintenance, connections) is safe and must pass after UI changes, with selectors updated in the same change. e2e/runs.mjs also covers run titles on the mock adapter: a 6+ word prompt gives a 4-word tab, sidebar and run-window title with the full prompt in the tab tooltip, and `[mock:title-fail]` falls back to the prompt excerpt.
- e2e scripts and CI never touch the real user data directory: they set ORGAI_DATA_DIR.
- Release builds for each mac arch run on a native runner. Never cross-arch install the native CLIs.
- New dependencies are pinned to exact versions like the rest of package.json.
- SDK and provider behaviour claims are verified with a smoke script and recorded in CLAUDE.md with the version, or marked unverified there.
- Worktree commit and merge belong to the harness. Never register WorktreeCreate or WorktreeRemove hooks just to observe.
- Each feature lands as one descriptive commit plus a merge commit ('Merge <feature>').
- Branches: dev is the integration branch, main is stable and protected; releases are v<version> tags on main (release.yml refuses other refs). Agent runs happen on dev.
- Build output (out/, release/, release-*/, *.tsbuildinfo) is gitignored. Never commit it.
- Permission cards never clip a command silently: a Bash command is shown in full in a scrollable block, the title carries a "(+N lines)" or "(long command)" marker, and the header shows a "Command" badge (or "N lines" / "Long command" for multi-line or long ones) for every Bash call. In compact mode (body collapsed) every Bash card with a command focuses the Details toggle instead of the primary action (`DecisionCard` `focusDetails`, a no-op outside compact; also set for broad rule requests). Bidi and control characters in a command are shown as visible `\uXXXX` escapes with a "Hidden characters" badge.

## Commands

- Install: `npm install`
- Dev (hot reload): `npm run dev`
- Dev without tokens: `ORGAI_MOCK=1 npm run dev`
- Free local gate (typecheck, unit tests, build, e2e:free): `npm run check`
- Typecheck: `npm run typecheck`
- Unit tests: `npm test`
- Build: `npm run build`
- E2E (free, needs build): `npm run build && npm run e2e:free`. Each script uses a fresh temp data dir, or ORGAI_DATA_DIR if set.
- E2E (spends tokens): `node e2e/setup.mjs --yes | node e2e/history.mjs --yes | node e2e/worktree.mjs --yes`
- Smoke, spend tokens, consent required: `node scripts/smoke-codex.mjs --yes`, `node scripts/smoke-litellm.mjs --yes`, `node scripts/smoke-skills.mjs --yes` (not run yet). Without --yes, smoke-litellm only lists models and is free.
- Connector probe, token-free but uses the network, consent each time: `npm run probe:connectors -- --out docs/connector-probe-<date>.json` (`--list` parses the catalog offline, `--only id,id`). Last run 2026-10-31.
- Team assistant offline: `ORGAI_MOCK=1 npm run dev` reads seeded fixtures under `<data>/mock-home` and outside fixtures; no network, no tokens. Capabilities unit tests: `npx vitest run src/main/capabilities src/main/ipcCapabilities.test.ts`.
- Package Windows: `npm run dist` or `npm run dist:win`
- Package unpacked dir, no publish: `npm run pack` (not `npm pack`, which is npm's own tarball command). `npm run dist:dir` also builds an unpacked dir.
- Package macOS: `npm run dist:mac` (signed when an identity is available) or `npm run dist:mac:unsigned`. Per arch, on a machine of that arch: `npm run dist:mac:arm64`, `npm run dist:mac:x64`
- Regenerate icon: `npm run icon`
- Release: bump version on dev, merge dev → main by PR, `git tag v<version> && git push origin v<version>`

## Risks and gaps

- Codex:
  - It is unverified that dynamic tools (the harness tools) survive thread/resume. The adapter's MCP restart and run continuation assume they do.
  - All Codex, LiteLLM and MCP-registry wire shapes come from docs and schemas until smoke-codex and smoke-litellm run with your consent.
  - The device-code expiry field is a guess.
- Claude:
  - Env isolation and the truthful Anthropic status are unit-tested; no live run has confirmed which credential the bundled CLI picks with the isolated env, nor the live shape of an auth failure (assistant `error: 'authentication_failed'` comes from the 0.3.312 typings). `--setting-sources project` on `auth status` was checked token-free against a temp CLAUDE_CONFIG_DIR only.
  - settingSources ['project'] still loads the project repo's .claude/settings.json, whose env block (ANTHROPIC_BASE_URL and the like) or apiKeyHelper is applied by the CLI after OrgAI builds the child env. A hostile repo could reroute a run and capture its credential. Pre-existing; needs flag-level overrides or dropping 'project'.
  - Possible next step: a dedicated CLAUDE_CONFIG_DIR under the data dir for full isolation (it would also move the login and Keychain entry, so the user would log in inside OrgAI).
  - Other secrets in OrgAI's own environment (OPENAI_API_KEY, GITHUB_TOKEN and the like) still reach the Claude child and agent Bash; the denylist only covers routing.
  - Calling agents are attributed by tool_use id from extra._meta (the key is unverified), else first-in-first-out per tool name. FIFO can misattribute concurrent calls.
  - Query.setMcpServers for mid-run installs is unverified at runtime.
- macOS is untested by hand. The user tests on a MacBook with docs/macos-testing.md. Packaging and entitlements are unverified.
- The CI and release workflows have not had a first real run yet. Open:
  - winCodeSign extraction with signAndEditExecutable true on windows-latest.
  - Whether macos-15-intel is really x64 (the release job checks process.arch).
  - e2e:free on the mac runners, including a possible Keychain prompt for safeStorage.
  - Unsigned mac dmg/zip output, and whether hardenedRuntime without an identity causes trouble.
  - The publish job end to end.

- Run titles (docs/design/ux-review-run-titles.md): the renderer uses the title everywhere a run is named.
