## Release 0.1.3

### MCP servers: harness library, project picks, OAuth authorization
- **MCP library** (App settings): define servers once, with credentials and OAuth authorization kept at the library level (`<data>/mcp-library.json`, secrets in safeStorage). Add from the registry, by hand, or with **Configure with AI** (a library-scope assistant run on the virtual `harness` project).
- **Project settings**: "From your library" (linked by reference, enable + role access per project) and "Only in this project" groups; **Add from library**, **Add to library** (promote), unlink.
- **Authorize** remote MCP servers: OAuth discovery (RFC 9728/8414), PKCE S256, `resource` indicator, DCR or a pre-registered client id/secret (needed by servers such as GitHub's hosted MCP that refuse dynamic registration), one-shot loopback redirect, refresh with rotation. Tokens never cross IPC; the bearer header is injected per run and only when the token's resource matches the server URL.
- **AI at both levels**: the project MCP assistant picks from the library first and saves new servers to the library unless project-only; setup runs get an optional "Suggested tools" proposal from the library (skippable, never blocks setup); install cards gain a "This project and library" scope.
- Codex: OAuth bearer goes through `bearer_token_env_var`, never argv. Claude: bearer redacted from logs.

### Security hardening (two Reviewer passes, no critical/high open)
- Install-card edits are allowlisted onto the agent's spec and cannot reuse an existing server id; run-scoped servers never read stored secrets.
- OAuth fetches: no redirects, 64 KB body cap, https-only server-named URLs (loopback only for loopback servers), private-IP literals refused, per-authorization-server client reuse, exact state match on the callback.
- Proposals that retarget an existing server drop its stored secrets; safe id alphabet for servers and projects; `projects:save` refuses unknown ids.
