# OrgAI UX review (live walkthrough)

Reviewer: UX Researcher. Commit reviewed: `35c0a2c` (branch `worktree-agent-ac02e87cea772adec`, `out/` rebuilt with `npm run build` first).
Companion: `ui-review.md` (older, source-based, commit `6eab480`), `spec.md`, `plan.md`.

## 0. How this was walked

- The built app was driven with playwright-core (`_electron`) from a throwaway driver kept in `e2e/shots/ux/_t/` (gitignored). It launches `out/` with `ORGAI_MOCK=1` and a fresh temp `ORGAI_DATA_DIR`, then reads JS snippets from a command file so one session can be explored step by step.
- Window sizes: **1424x881** and **1100x700** (also 1024x640 once, the app minimum). Themes: dark (default) and light, switched by setting `data-theme` on `<html>`, because the app has no way to do it (finding H2). One keyboard-only pass (Tab, Shift+Tab, Enter, Space, Escape) on Projects, the org chart and the live view.
- Screenshots are in `e2e/shots/ux/` (path form `e2e/shots/ux/<name>.png`). The folder is gitignored; a subset used as evidence below was force-added to git so it travels with the branch. Names in the tables are the file stems.
- Flows walked: first launch, create a project (both modes), delete, mock toggle, setup (Architect) on mock and, by accident, on a real adapter (see the note below), org chart editor, live runs (permission, question, rule-request, MCP-install, proposal cards, plan tab, interrupt, end session, continue, image paste), history after an app restart, app settings, project settings, connections, MCP (manual form, registry search and select, test failure, Configure with AI), remap notice and preview dialog, permission rules.
- **Not walked, and why:** merge-review cards, branch discard and the worktree flow (the mock adapter does not create worktrees; `e2e/worktree.mjs` spends tokens). Codex "Sign in with ChatGPT" and LiteLLM "Test and connect" (would start a browser login or hit a network proxy; only the unconfigured state was looked at). Plugins "Add plugin" (native folder picker). Native `confirm()` dialogs (outside the page, so not screenshot-able; their text was captured through the dialog hook). macOS. The default mock script's MCP assistant run proposes an unpinned package and is rejected by the validator, so no MCP proposal card appeared (mock script issue, not a UX finding, but the transcript then says "The MCP servers are set up.").
- **Spend disclosure.** `ORGAI_MOCK=1` only *registers* the mock adapter. A project runs on it only when its provider is set to mock. My first project was created through the form with "Skip AI setup" unticked, so it started a **real** Architect session on the Claude login (two turns, about 0.03 USD API-equivalent on Opus, ended and deleted). Every later run used the mock. This is also finding M3: there is no way to create a project on the mock from the form.

Severity: **High** blocks or misleads a first-time user on a main path, or is a defect they will hit within minutes. **Medium** costs time or trust but has a workaround. **Low** is polish.

## 2. What works well (do not break)

- Live-view empty state: "Give Lead something to do" with the role chips and the three-line explanation. It uses the real orchestrator name.
- Agent node anatomy (avatar with state ring, role and model, activity string such as "Delegating to implementer" / "Needs approval: Editing example.ts", token and cost footer), the done-group node `1 done ▾`, and the legend.
- Composer clarity: "Replying to Lead", "Answering the Architect", "New run: 1 open run keeps going", "Continuing this session (run from just now)", and "This run was continued by a later run. Open it" are good.
- Run history rows: kind chip, status, cost, "Started 7 min ago · session of 2 runs", "Continued from … / Continued by …" links, Open / Continue / Retrospective actions. History survives restart and reopening keeps the tab.
- Dialog primitive (MCP manual form, registry, Configure with AI, remap preview): Escape closes, title, helper text, sticky footer, focus lands in the first field. The registry flow (search, select, "Command that will run", "Pinned to version", env var hints, role access) is a good trust pattern.
- "Review changes" before remapping models, with a before/after table and "The result is shown after applying, with Undo."
- Connection status badges and tier mapping explanation ("Top / Deep / Everyday / Fast" with plain sentences).
- Focus ring is consistent and visible in dark and light (contrast of `--text-tertiary` now 5.4:1 dark, 5.0:1 light, white on accent 5.2:1 and 6.2:1).
- `prefers-reduced-motion` is honoured (`global.css:117`).
- The light theme renders cleanly where it can be reached (canvas dots, nodes, chips, cards).
- Project settings copy is specific and honest (cost cap "On a subscription this is a safety cap, not money you are billed"), and the mock toggle states what it does.

## 6. Reproduction

From the worktree root, after `npm run build`. Nothing touches the real profile.

```sh
# 1. fixture repository (an existing-repository project) in a temp folder
node -e "import('./e2e/lib.mjs').then(m=>{m.makeFixtureRepo('ux',{at:'C:/Users/<you>/AppData/Local/Temp/ux-repo1'});process.exit(0)})"
# 2. drive the built app on a fresh data dir with the run-desktop skill (stdin REPL: launch, click, type, ss, eval, quit)
ORGAI_MOCK=1 ORGAI_DATA_DIR="C:/Users/<you>/AppData/Local/Temp/ux-data-1" node .claude/skills/run-desktop/driver.mjs
# 3. optional, for the question / rule-request / MCP-install cards: a custom mock script (JSON MockScript, see mock.ts)
ORGAI_MOCK=1 ORGAI_MOCK_SCRIPT="<path to script.json>" ORGAI_DATA_DIR=<same dir> node .claude/skills/run-desktop/driver.mjs
```

My own session used a throwaway file-queue variant of that driver (kept untracked in `e2e/shots/ux/_t/`) so snippets could be sent without a TTY; it launched with exactly the environment above. Create the project with **Skip AI setup** ticked, then turn on **Project settings > Connection > Run on the scripted mock adapter** before starting any run or setup (M3). The script used for step 3 had a plan step, an `ask_user`, a `request_permission_rules` and a `request_mcp_install` step (registry name `io.github.Digital-Defiance/mcp-filesystem`, version 0.1.9; needs network for the registry lookup).
