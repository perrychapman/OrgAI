# Pocket Office: initial visual slice

Status: direction approved for expansion. Artwork is original, made for OrgAI, with no borrowed franchise assets. `generate-atlas.py` is the editable deterministic source for the paired PNG sheets and JSON metadata; the review SVGs are concept sources. Regenerate from the repository root with `python src/renderer/src/assets/pocket-office/generate-atlas.py` using Python and Pillow 12.3.0, the authoring version used for these exports. Pillow is an authoring dependency only, not an application runtime dependency. The four-frame delivery storyboard is not a finished animation.

## Direction and contract

Use a full-color handheld-inspired office on a 16 × 16 grid, with crisp outlines, warm floors and wood, green plants, varied workers, and nearest-neighbor integer sprite scaling. `color` is the default scene palette; `neutral` and `green` remain optional four-shade alternatives. Scene palettes are independent of the application theme. Normal application typography, shared CanvasFrame, toolbar, inspector, icons and semantic tokens remain outside the art. Check actual text and focus contrast in both themes; do not use artwork colors as UI text tokens.

Production assets live under `src/renderer/src/assets/pocket-office/`: deterministic editable sources, transparent `tiles-{color,neutral,green}.png`, `props-{color,neutral,green}.png`, `workers-{color,neutral,green}.png`, and `atlas.json`. All palettes share identical dimensions and coordinates, so switching requires no filter. The metadata contract is version 1, with `tileSize: 16`, named palettes and named frame records `{x,y,w,h}` in integer source pixels from the top left, without implicit padding. The renderer crops by name, never by packing order, and uses nearest-neighbor sampling. The color palette is multicolor throughout the sheet, not limited to the four representative values in `palettes.color`.

## Building composition

Each actual direct child of the root defines a department; its descendants share that department. Label it using the actual lead name, with explicit prior-session context where applicable; the root occupies a central area. Link rooms with visible wall openings and walkable corridors. Overflow uses numbered rooms or floors; same-floor messages can walk through corridors, while cross-floor messages get an immediate labeled cue without a fictional walk. Make counts and floor navigation explicit; never invent reporting relationships. Rooms and corridor bounds respond to the available canvas and fill it rather than leaving a fixed small room in one corner. Furniture and aisle layout adapt to size while collision and route connectivity remain valid. Keep readable, normal-size department labels and worker names/status overlays independent of sprite zoom, with visible selection and focus; prevent labels from obscuring doors, paths or controls. Maintain accessible roster and inspector access at every size. The [building concept](../../src/renderer/src/assets/pocket-office/review-color-building.svg) shows intended spatial relationships; its names and agents are illustrative sample data.

Worker frames are 16 × 24 with feet pivot `[8,23]`. Stable names are `worker.<silhouette>.<direction>.<pose>`: directions `down`, `left`, `right`, `up`; poses `idle`, `walk-1`, `walk-2`, `work`, `wait`, `done`, `error`. Metadata lists every supported name explicitly, even where static poses share a rectangle. Six to eight silhouettes are assigned stably by agent ID, never by state or color. There is no idle animation.

Each prop record specifies `frame`, `placement`, `footprint`, `interactionAnchors`, and `depthAnchor`. The footprint lists blocked grid-cell offsets from the placement origin. Each interaction anchor names an adjacent unblocked walkable cell offset and a facing; desk anchors must connect to an aisle. The depth anchor is an integer pixel position in the prop. Sort objects by feet/depth y, with foreground pieces above workers separately. `crt`, `crt-side`, and `mug` are tabletop details: layer them over a supporting desk and do not add a second floor obstacle. All other props use the conservative 2 × 2 footprint listed in metadata.

Tile ID families: `tile.00`–`.07` floor (00 plain, 01 horizontal seam, 02 vertical seam, 03 both, 04–07 sparse marks); `.08`–`.15` wall (08 straight, 09 left edge, 10 right edge, 11 both, 12–15 repeat those variants); `.16`–`.23` rugs (16 plain border, 17 inset, 18 stripe, 19 inset and stripe, 20–23 repeat); `.24`–`.31` doors (24 plain, 25 upper panel, alternating); `.32`–`.39` partitions (32 plain, 33 center post, alternating); `.40`–`.47` floor details (40 solid, 41 inset, 42 stripe, 43 inset and stripe, then repeat). Prefer plain floor and sparse seams so furniture remains legible. Stable prop and worker IDs and crop rectangles are in `atlas.json`; import it and the selected palette's PNGs as assets, not inferred array offsets.

## Interaction and motion

Live Run retains its toolbar, selection and inspector. Team uses static role desks and its existing edit controls. Settings identifies sample data. A readable parallel agent list supplies names and status words; use native buttons with non-overlapping targets of at least 24 × 24 CSS pixels, visible token focus, and a selection cue distinct from status. Tab reaches scene controls and the list; Enter or Space selects an agent and opens the existing inspector. Escape closes the style popover and restores focus. Reuse the frame announcement for selection and style changes; never announce animation frames.

Keep a visible Agents roster with current, finished and earlier-session agents, with session and group context that distinguishes ambiguous handles and inspector parity; none requires switching to Graph. The office roster may directly expose loaded agents instead of duplicating Graph's “Show reports under {name}” and “Earlier: {n} agents” controls, provided “Load earlier sessions” reaches unloaded history and folded reports remain reachable. In both Canvas style popover and CanvasSection, put the named Presentation radio group (Graph, Pocket Office) first and the Office palette group (Color, Neutral, Green) adjacent when Office is selected. Canvas style remains the single toolbar entry; show its text where space permits. Say “Applies to Live, Team and the sample preview.” Label the saved gallery “Graph style” and say “Choose a graph style to switch to Graph.” Choosing one returns to Graph; switching presentations preserves graph preferences. Settings visibly says “Sample office · example agents”; Team says “Team layout · roles, not live activity.” Preview is inert. Historical inspection never replays walks. At 1024 × 640, Presentation precedes the sticky sample and a named scroller keeps roster and earlier/finished controls reachable. At both sizes opening the popover focuses the checked presentation radio; Escape returns to Canvas style, and one selection announcement speaks without a preset timer stealing focus.

Animate only actual new `agent.message` events; delivery illustrates a message already sent and does not gate it. Do not fabricate thoughts or imply live-only events can replay. Cap at three concurrent walks and twelve queued, discard backlog older than eight seconds, and combine bursts by endpoints. Stop visual work when hidden, unmounted, reduced motion is active, or routes become obsolete. Reduced motion presents immediate static message and status indicators. Captions use available text, visibly indicate shortening and leave full available content in the inspector. Handle empty, single-agent, waiting, failed, finished, removed-agent and large-team states; large teams use stable rooms and readable counts.

Proposed selectors: `pocket-office-scene`, `pocket-office-agent` with `data-agent-id`, `pocket-office-agent-list`, `pocket-office-room`, `pocket-office-message`, and `pocket-office-preview`. Settings keeps `canvas-announce`; use the existing frame live region elsewhere.
