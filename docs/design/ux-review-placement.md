# OrgAI UX review: placement, hierarchy and brand feel

Reviewer: UX Researcher. Companions: `ux-review-2.md` (A1-A19), `ux-review-runs-3.md` (N1-N13). Those findings are not repeated unless placement makes them worse.

## 1. Header

- **Commit reviewed:** dev HEAD `1108b74`. `npm run build` was run first; `out/` was driven.
- **Method:** playwright-core `_electron`, same launch as `e2e/lib.mjs`, from two throwaway drivers under `e2e/shots/ux/_t/` (`placement-walk.mjs`, `placement-walk2.mjs`). Environment: `ORGAI_MOCK=1`, a fresh temp `ORGAI_DATA_DIR`, `ORGAI_MOCK_SCRIPT` with a plan, a spawn, two background Edit/Bash permission asks, a `request_permission_rules` call and an `ask_user` question so the decision tray was open. Every project was created with "Use the mock adapter" ticked; no tokens were spent and the real profile was never touched. Light theme was switched through Settings > Appearance. One keyboard pass (Tab order over the Live view) was recorded.
- **Sizes:** window 1024x640 (inner viewport 1008x641), 1424x881 (1408x842) and 1600x1000 (1584x961), dark and light. Measurements below are inner viewport pixels.
- **Walked:** first launch and New project form, Projects grid, sidebar, topbar, Live (empty "New run", running with 3 decisions, rule request plus question, idle, ended with "Org retrospective"), History, Org chart, project Settings, app Settings (Appearance, Connections, MCP library, About).
- **Not walked:** a setup (Architect) session with proposal cards, the MCP install card, Defaults for new projects, and a real (non-mock) connection state.
- **Shots:** `e2e/shots/ux/placement/<name>.png`. Raw measurements: `e2e/shots/ux/placement/measure.jsonl`.

Severity: **High** hurts the main path or the first impression at a supported size. **Medium** costs scanning time or trust. **Low** polish.

## 2. Top 10, ranked by user impact

1. **P1 (High)** Live view at 1024x640 with a decision open: the canvas is 216 px wide, the zoom control sits on top of a node, and three columns fight for 776 px.
2. **P2 (High)** 139 px of chrome (three stacked rows) sits above the canvas at every size, and the run header packs about 9 items into one row that truncates the run title at 1024.
3. **P3 (High)** "Needs you" is shown in 8+ places at once, and the sidebar attention block (about 190 px) is the loudest thing on screen. It pushes the project list below the fold at 1024.
4. **B1 (Medium)** The brand is almost absent from the UI: 26 px logo, a plain wordmark, no gradient anywhere, so the app looks like a generic dark dev tool, not like the logo.
5. **B2 (Medium)** Colour collisions: the brand purple is also "working" and the Orchestrator role; orange is "Mock mode", "Needs you" and the Researcher role; green is "done" and the Reviewer role.
6. **P4 (Medium)** The sidebar footer (usage meters, account pill, Refresh) is 237 px tall at 1424, more than twice the project list it sits under.
7. **P8 (Medium)** Org chart: the AI drafting panel (360 px, the only purple button) outweighs the chart; the real editing actions are ghost buttons; two nested headings say the same thing.
8. **P5 (Medium)** Topbar: the long working-directory pill truncates the meaningful end of the path, and the Saved indicator is clipped to "Save" / "Saved 0" at 1024.
9. **P6 (Medium)** Two tab idioms stacked directly on each other (segmented control for project tabs, browser-style tabs for runs).
10. **P14 (Medium)** New project form at 1024: the primary "Create and start setup" button is below the fold, and at 1600 the form hugs the left with 60% of the page empty.

## 5. Keep

- One button hierarchy: a single purple filled primary per screen region, ghost secondaries and a red "End session" that is visibly different (Projects "New project", tray "Allow once").
- The decision card shell: kind chip, agent avatar, the command as monospaced text, "Allow once: this call only." and Deny on the right. Consistent across question and permission (`20-cards-rule-dark-1024`, `22-idle-dark-1024`).
- The empty "Give Orchestrator something to do" page: one sentence, role chips as a preview, one input (`04-live-empty-dark-1424`).
- The new-project form copy: inline help under each field, a checkbox explaining the Architect, a visible reason next to the disabled button (`01-first-launch-dark-1600`).
- Settings sub-nav with a sticky left column; "App settings" and "Project settings" as distinct page titles (`12-appsettings-dark-1424`, `10-psettings-dark-1424`).
- Status vocabulary: the same seven words everywhere; tab group order Live, History, Org chart, Settings.
- Dark and light parity; tokens hold in both themes (`10-live-light-1424`, `10-org-light-1600`).
- History table: columns, status pill, "Viewing" marker, "Open" action (`10-history-dark-1424`).
- The org chart footer hint (drag, Enter, Delete) and the ghost toolbar placement above the canvas.
- Skip link and visible purple focus ring.
