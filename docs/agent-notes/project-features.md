# Project features

Agent import, run outputs, team files, practice kit, repository clone, folder config trust. Moved out of CLAUDE.md on 2026-11-07; see CLAUDE.md for the index.

## Main

- Agent import (`src/main/setup/import/`, `AgentImportService` in `importer.ts`): `projects:scanAgents` (never
  rejects), `projects:previewImport`, `projects:applyImport` (returns `previousRoles` for Undo), `projects:exportOrg`
  (`.orgai/org.json`, format `orgai.org/1`), `ProjectCreateInput.importAgents` and the `ProjectPathCheck` extras
  (`agentSources`, `instructionFiles`, `existingProjectId/Name`). Sources: OrgAI export, Claude Code, opencode, Codex,
  Copilot, Gemini CLI, Kiro, Roo; AGENTS.md/CLAUDE.md-style files are listed, never roles. Models map to the project's
  connection (`model.ts`, `importTierForModel` in defaults.ts: kept, tier, or 'everyday' default). Preview and apply
  re-scan the stored project's folder (the renderer sends choices, at most 200, never roles); apply requires the
  preview's `digest` (`AgentImportApplyInput`) and refuses a missing or stale one. Items carry the whole `prompt` and
  `elevatedTools` (Bash, Edit, Write, NotebookEdit, 'canSpawn') for the UI to show. A definition with no tool list
  gets read-only Read, Glob, Grep; a 'replace' keeps the old role's MCP grants with a "Keeps MCP access" note.
  The repo is untrusted: absolute roots, realpath-confined regular files outside .git only, no process or network,
  4,000-char YAML lines and linear parser regexes (timing-tested), hard caps (see ARCHITECTURE.md
  Conventions). Every parser is verified only by fixtures written from the docs, not by files the other harnesses
  produced; Copilot, Gemini, Kiro and Roo are best-effort. No renderer code uses it yet.

Index `<data>/projects/<id>/outputs.json`. Previews in main never ship HTML (`OutputPreview`); mammoth always `externalFileAccess: false`; zip guard plus per-entry inflate verification before mammoth / exceljs; docx stops at `DOCX_PREVIEW_MAX_XML_BYTES` (3 MB), xlsx at `XLSX_PREVIEW_MAX_XML_BYTES` (8 MB), xlsx over every non-image entry, docx over only the parts mammoth reads, no entry over 16 MB is read, docx images are read only for image/png|jpeg|gif|webp through a read-bytes budget, and previews run one at a time with at most 8 pending (ARCHITECTURE.md Risks). `outputs:open` opens only allowlisted extensions of the real file; reveal and saveAs re-check the path.   - Outputs 2, Phase B (main only; spec `docs/design/outputs-2.md`, ARCHITECTURE.md "Run outputs"): an output is one file (case-folded real path); produce / register of an indexed path from any run adds a version (same digest: "No change; still version N"), an unindexed existing path or `separate: true` gets " (2)", `overwrite` is ignored, `.pptm` refused, old "(2)" outputs not merged. - Team files (`src/main/teamFiles/`, `TeamFilesService`, `teamFiles:*` IPC, `TEAM_FILES_IPC`, `window.orgai.teamFiles`, `onTeamFilesChanged`; ARCHITECTURE.md "Team files"): a code project's team as files in its folder (`.orgai/team.json`, `agents/<slug>.md`, `skills/<name>/`, `mcp.json`) so git carries it. Project stays the cache that every reader uses; files win through a gate because the repo is untrusted. Pure parse, serialize, digest, gate, delta and project mapping are apart from disk, store and service. Digests cover parsed content, never bytes.
  - Every main-process save goes through `ProjectStore.save`'s hook and counts as approved: ingest first, then apply the delta to approved and to the disk doc (never the cache), so a pending change in a file survives. A hook failure never fails a save (`dirtyBefore`, retried at a check). `saveInternal` bypasses it. Folder checks happen at open (`teamFiles:status`, which also does the one first write), focus and run start.
  - The approval baseline (`<data>/projects/<id>/team-files/`, `approved.json` and the snapshots) is a self-control
    protected path (PR 47, `teamFiles/protection.ts`): agent file tools and shell commands that name a path at or under it
    are denied, for every current project id (re-read per check, both spellings) and the sibling product's existing
    projects. Checked by `protection.test.ts` and `bootstrap.test.ts` (unit, temp folders). Open limit: a copy or move
    into a parent folder (`<data>/projects/<id>/`) is not seen as touching it (cli-host.md, PR 47 bullet).
  - `gate.ts` is the one place that decides what needs approval (rules in ARCHITECTURE.md), and `TRIVIAL_TOOLS` / `isElevatedTool` the one tool list. Unknown tools are elevated. Never list a change the digest does not bind (`omittedChanges` refuses approve and create).
  - Never destructive: a missing or unreadable team is a problem and is never overwritten; a server gone from the files keeps its secrets and id (tombstones). Never for engagements, virtual projects or a project sharing another's folder (`offReason`). Never commit or push automatically (`commitPaths` on request only).
  - A live run takes only the items an approved change names (`setLive`, `overlayOwnItems`); pass `own` for servers and skills. Verified by unit tests, real git in temp repos and the mock; nothing on two real computers, macOS or Linux, and no renderer yet.
- Practice kit (`src/main/kit/`, `KitService`, `kit:*` IPC, `window.orgai.kit`; ARCHITECTURE.md "Practice kit"): library skills,
  library MCP servers, custom connector presets and team templates in one `*.orgai-kit.json` (`orgai.kit/1`, at most 50 MB).
  Secret values, OAuth state, tokens, `connectedAt`, `buildDigest` / built files, connector entries and ids never go in it;
  export leaves such items out with a note. Paths come only from main's save / open dialogs (`PickedPaths`; an export path
  is consumed by a successful export). Import is untrusted: items are rebuilt and validated (shell-injection skill bodies,
  hidden characters, pinned versions, preset rules, caps) and a bad item is refused alone. `kit:previewImport` gives the
  sha256 `digest` and per-item status (new / same / different / refused); `kit:applyImport` refuses a missing or stale digest
  and applies only the chosen items (add, replace, copy, skip). A replace of a server clears its stored secrets and sign-in;
  `needsSecrets` lists the slots to fill in. No undo, no renderer yet. Unit-tested only (`kit.test.ts`).
  Review fixes: export and import both refuse a server whose plain argument, env value, header value or address carries a
  credential (URL userinfo, key-shaped values, credential-like names incl. key / pat / dsn / private; pattern checks, not a
  guarantee), import adds the outside-source rules (https, no private address, `reviewTarget`, no run-changing slot names)
  to servers and preset variants (`connectorPresetsKitSave` too), templates are stored rebuilt from parsed roles and
  `KitPreviewItem.roles` shows prompts and elevated tools, skill paths use `safeKitRelPath`, skill export drops private-looking
  files, and an export target whose suffix was added here is refused when it exists (`kitExportTarget`).
