Agent import, run outputs, team files, practice kit, repository clone, folder config trust. Moved out of CLAUDE.md on 2026-11-07; see CLAUDE.md for the index.

## Main

- Agent import (`src/main/setup/import/`, `AgentImportService` in `importer.ts`): `projects:scanAgents` (never
  rejects), `projects:previewImport`, `projects:applyImport` (returns `previousRoles` for Undo), `projects:exportOrg`
  (`.orgai/org.json`, format `orgai.org/1`), `ProjectCreateInput.importAgents` and the `ProjectPathCheck` extras

  connection (`model.ts`, `importTierForModel` in defaults.ts: kept, tier, or 'everyday' default). Preview and apply
  re-scan the stored project's folder (the renderer sends choices, at most 200, never roles); apply requires the
  preview's `digest` (`AgentImportApplyInput`) and refuses a missing or stale one. Items carry the whole `prompt` and
  `elevatedTools` (Bash, Edit, Write, NotebookEdit, 'canSpawn') for the UI to show. A definition with no tool list
  gets read-only Read, Glob, Grep; a 'replace' keeps the old role's MCP grants with a "Keeps MCP access" note.
  The repo is untrusted: absolute roots, realpath-confined regular files outside .git only, no process or network,
  4,000-char YAML lines and linear parser regexes (timing-tested), hard caps (see ARCHITECTURE.md
  Conventions). Every parser is verified only by fixtures written from the docs, not by files the other harnesses
  produced; Copilot, Gemini, Kiro and Roo are best-effort. No renderer code uses it yet.

    projects. Checked by `protection.test.ts` and `bootstrap.test.ts` (unit, temp folders). Open limit: a copy or move

- Commit activity (`projects:commitActivity`, `src/main/projects/commitActivity.ts`, `gitCommitTimes` in `runtime/worktrees.ts`): per-project commits for the last seven local days, desktop IPC only. A project folder is attacker-influenced content, so git here must never run anything the folder chooses, read elsewhere, reach a network or hang. Git runs as `git --no-pager -c core.fsmonitor=false -c core.hooksPath=<null device> -c core.pager=cat -c core.sshCommand=false -c core.askPass= -c log.showSignature=false -c gc.auto=0 -c maintenance.auto=false log --no-merges --no-show-signature --since=<local midnight 6 days ago, ISO UTC> --max-count=5000 --format=%ct HEAD --` (`commitTimesArgs`; the `--` keeps a working-tree file named HEAD from making the revision ambiguous), spawned without a shell with the git binary found by `gitExecutable`, stdin and stderr ignored, cwd the project folder. The complete environment (`readOnlyGitEnv`): the parent environment after `scrubControlEnv` with every inherited `GIT_*` variable dropped, plus exactly `GIT_DIR=<root>/.git`, `GIT_WORK_TREE=<root>`, `GIT_NO_LAZY_FETCH=1` (git 2.44+), `GIT_ALLOW_PROTOCOL=orgai-none` (a name no transport has, so no protocol is allowed whatever the repository's own `protocol.*.allow` says; this is what also stops a lazy fetch on git older than 2.44), `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`, `GIT_PAGER=cat`, `GIT_NO_REPLACE_OBJECTS=1`. `GIT_CONFIG_NOSYSTEM` is deliberately not set: it discarded an administrator's system hardening and added no protection (the global and system config files are not repository content). It runs only when `<root>/.git` is a real directory (`hasPlainGitDir`: `lstat`, not a file, not a symlink or junction): a `.git` file (a `gitdir:` redirect, which on Windows could name a UNC path and leak NTLM credentials, and also every linked-worktree project) and a subfolder of another repository are `available: false`, and the pinned `GIT_DIR` means an empty or invalid `.git` directory fails instead of making git search upward into a parent repository. Pinning `GIT_DIR` skips git's `safe.directory` ownership check, which is why the environment and the `.git` check are the defence. The `-c` overrides are defence in depth: `git log` with a piped stdout reaches none of fsmonitor, pager or ssh, and no test shows them stopping anything. Kill: a 5 s timer, the 5000-line cap and a >1 KiB partial line stop git and its tree with `killProcessTree` (win32: `%SystemRoot%\System32\taskkill.exe /PID <pid> /T /F`, absolute path, argument array, no shell; POSIX: git is spawned `detached` and the process group is signalled; either falls back to killing the direct child), and the shutdown registry (`trackChildProcess`) gets a wrapper whose kill is the same tree kill. Cache: one in-flight promise per project key, reused while it is pending (a second call during a slow batch never queues git again, so the waiting list is bounded by the number of listed projects); the 60 s starts when a run settles. Folder trust is not git protection: `folderConfigLoadsNow` covers the folder's agent config (hooks, MCP, skills) and state `none` passes it, so a hostile `.git/config` is stopped only by the environment and the `.git` checks above. Any git failure, empty repository or missing folder is `available: false`. Verified by `commitActivity.test.ts` (Windows, git 2.47.0: fixed-clock bucketing at 23:59 / 00:00, a year-long sweep for DST, fake-git service limits, cache and the pending-run reuse with a slow fake git, the exact environment keys and the argument tail, and real temporary repositories with set commit dates, a merge, a non-repository, a missing folder, an empty repository, an untrusted folder, a tracked file named HEAD, a `.git` file with a `gitdir:` line, an empty `.git` directory inside a repository with commits, and a fake partial clone whose HEAD commit object is missing and whose promisor remote has `uploadpack` set to a program that writes a marker: the marker must not appear and the result is `available: false`, and with the two environment variables removed the marker does appear, each variable alone being enough on 2.47; plus the taskkill / group-signal argument tests and a real parent-with-grandchild tree that `killProcessTree` ends where `child.kill()` leaves the grandchild running). Unverified: macOS and Linux (the POSIX group kill is only tested through an injected signaller), the Git for Windows launcher chain (`git.exe` to `git-core` children) under `taskkill /T` on a slow `git log` (the real tree test uses Node processes), git older than 2.44 (`GIT_NO_LAZY_FETCH` unknown there; `GIT_ALLOW_PROTOCOL` is the claimed cover and was not run), very large repositories, and history with skewed commit dates (git's `--since` stops walking at the first too-old commit, so such a history can undercount). `hasPlainGitDir` also refuses a `.git/commondir` file and any `.git/objects/info/alternates` with a non-empty line (read capped at 64 KiB, a read error is a refusal), so a repository borrowing another's objects or a UNC store is `available: false`. Residual risk: `include.path` / `includeIf` in the repository's own config name paths git reads without a transport; they cannot be disabled with `-c` and are not blocked (read-only reads of attacker-named locations; on Windows a UNC path can still cause an SMB authentication attempt). Kill hardening: `killProcessTree` skips the tree kill for a child that already exited (`exitCode` / `signalCode` set, the pid may be reused) and on win32 falls back to `child.kill()` when taskkill exits non-zero (fake-spawn tests only). Open: the folder-trust scan (`folderConfigLoadsNow`) runs synchronously on the main process on a cold cache, up to 50 projects (L5, left as is).

- Hybrid evolve call (2026-11-25, self-healing efficiency step 5; `docs/design/self-healing-efficiency.md`; the "digest"
  here is `synthesizer.ts` `buildDigest`, the text sent to the model, not a `RunDigest`). Facts, each with how it was checked:
  - Cooldown hint: roles in cooldown are listed on one `do not change` line (slugs through `safeLine`, deduplicated, at most
    12, absent when none cool); the digest stays under 2,800 characters and one fence (unit tested, `synthesizer.test.ts`,
    with a fence-breaking, key-bearing slug).
  - Memo: the ledger keeps `hybridMemo { digestHash, outcome, at }` (sha256 hex, `empty` | `refused` | `unusable` | `trimmed`,
    newest only). `empty` = the answer proposed nothing; `unusable` = not parseable JSON; `refused` = the gate refused the
    plan; `trimmed` = every proposed patch was trimmed away (before the memo that first pass applied nothing, so the memo
    hit returns the same empty gated plan, never the deterministic one: the memo may only remove calls, never change which
    plan is applied). A memo older than 14 days (`HYBRID_MEMO_MAX_AGE_MS`, `ratchet.ts`) is ignored and the model is asked
    again (unit tested, `service.test.ts` "hybrid memo"; `synthesizer.test.ts` checks first pass and memo pass give the same
    fingerprint for all four outcomes). A failed or timed-out call stores nothing. An identical digest hash makes no call and returns
    the deterministic plan with a rationale saying so; any change to the digest (runs, team, rejected list, cooldown) calls
    again (unit tested, `synthesizer.test.ts`).
  - Where written: `applyCore`, so the post-run pass and an explicit apply, under the project's serial chain through
    `writeLedger`. `analyze` reads the memo from its read-only ledger and never writes it (unit tested: analyze leaves no
    memo, a later pass writes one, a later analyze makes no call). Two post-run passes on an unchanged digest make one call
    after an empty or unparseable answer, two after a changed digest, two after a usable answer (unit tested,
    `service.test.ts` "hybrid memo", using team files in 'pending' so nothing changes between passes).
  - Storage: shape-checked on read (64 hex, enum, finite number; bad = dropped), an old ledger without it loads equal to an
    empty one (unit tested, `ratchet.test.ts`).
  - Unchanged: the deterministic strategy and the bench: `npm run bench:heal -- --seed 1` gave an identical `results.json`
    (without `generatedAt`) before and after. It only removes calls; live model answers were not run.
