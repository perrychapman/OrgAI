# macOS, packaging and CI

Platform notes and CI. Moved out of CLAUDE.md on 2026-11-07; see CLAUDE.md for the index.

- macOS is untested; nobody has run it on a Mac yet (`docs/macos-testing.md` is the checklist).
  - Dev app name: `predev` / `prestart` / `prepreview` run `scripts/mac-dev-app-name.mjs` (darwin only, pure argv in `scripts/lib/macDevAppName.mjs`): plutil sets the dev Electron.app's CFBundleName / CFBundleDisplayName to OrgAI, then copies `build/icon.icns` over the bundle icon (`CFBundleIconFile` read via plutil, default `electron.icns`, only when the bytes differ) and ad-hoc codesigns; never fails dev. Unit-tested with an injected runner and copier; real Mac behaviour (notification name and logo, Dock hover) UNVERIFIED.
  - App identity (`src/main/appIdentity.ts`): `APP_USER_MODEL_ID` is the single `com.orgai.app`. On Windows, `registerWindowsAppIdentity` writes `DisplayName` and `IconUri` under `HKCU\Software\Classes\AppUserModelId\com.orgai.app` with `%SystemRoot%\System32\reg.exe` via `execFile` argv (no shell, 5 s timeout, async, fail-open with one warn), so toasts in dev and the portable build show the name and logo without a Start Menu shortcut. `reg.exe` runs from a drive-absolute `SystemRoot` / `windir` (else `C:\Windows`) with an env of only `SystemRoot`, so provider keys in `process.env` are not inherited. The key is written only for unpackaged and portable runs (`shouldRegisterIdentity`: `!app.isPackaged` or `PORTABLE_EXECUTABLE_FILE` set by electron-builder's portable launcher); the installed NSIS build never writes it (its shortcut carries the id and no uninstaller would remove the key). `npm run dev` without `ORGAI_MOCK` / `ORGAI_DATA_DIR` therefore writes `HKCU\Software\Classes\AppUserModelId\com.orgai.app` on the developer's machine; remove it with `reg delete "HKCU\Software\Classes\AppUserModelId\com.orgai.app" /f`. Also skipped when `ORGAI_DATA_DIR` is set (e2e, CI) or `ORGAI_MOCK=1`, and for a refused folder or a lost lock. The portable build runs from a temp extraction folder deleted on exit, so `stableIconPath` copies `icon.ico` to `<userData>/app-icon.ico` (only when missing or a different size; fail-open with one warn) and that path is registered and used as the taskbar icon. Every window gets `win.setAppDetails`: unpackaged and portable pass appId, icon, relaunch command (portable: the quoted `PORTABLE_EXECUTABLE_FILE`) and name; the installed packaged build passes only the appId so a pinned app keeps its shortcut. Relaunch arguments are quoted without trailing backslashes. Mac dev icon: `iconDestination` accepts `CFBundleIconFile` only as a plain file name, else `electron.icns` (unit-tested, incl. `../../x`). Packaged builds find the icon in the resources root (`extraResources` in electron-builder.yml). Notifications carry no `icon` on Windows and macOS; on Linux only, `NotifierDeps.iconPath` supplies the PNG. Verified by unit tests (exact argv and minimal env, non-win32 no-op, registration decision, root validation, quoting, appDetails variants, icon copy with injected fs, missing icon, fail-open, Linux-only icon). UNVERIFIED: real registry write, portable launcher env and icon copy on a real portable build, installed-build taskbar behaviour without relaunch details, real toast rendering, taskbar hover, `extraResources` output of a real pack.
  - App icon: `npm run icon` (`scripts/make-icon.mjs`, pure parts in `scripts/lib/icon.mjs`, tested in `src/main/icon/makeIcon.test.ts`) writes `build/icon.png` (1024), `build/icon.ico` (16-256, Windows) and `build/icon.icns` (macOS, mark inset to ~80% with a transparent margin); commit all three together. In dev, `index.ts` sets the window icon (ico on Windows, png elsewhere) and on darwin `app.dock.setIcon` (never packaged). Verified by unit tests and file inspection; the Dock, Finder and taskbar rendering is unverified on a Mac.
  - `trustSystemCertificates(options?)` (`src/main/systemCerts.ts`, issue #16) runs after `applyShellPath()`, only once the single-instance lock is ours (a second launch that exits never starts the macOS reader), and the in-process `orgai` (`src/cli/inprocHost.ts`, option `systemCertificates`, default on) calls it right after taking `<data>/run/` ownership and stops the read when the host ends or the process exits (unit-tested with injected hooks; the real CLI path is unverified): `tls.setDefaultCACertificates` gets the defaults plus the OS store's certificates (deduplicated, fail-open) so main-process `fetch` trusts a corporate / inspecting root CA. Windows and Linux read the store synchronously. macOS never reads it on the main thread, except in launches with `--use-system-ca` where `getCACertificates('default')` reads the store (`getCACertificates('system')` can stall in the Security framework, nodejs/node#63313; public reports of 5 s to about 10 s, one of 107 s, anthropics/claude-code#76079): a child `process.execPath -e <script>` with `ELECTRON_RUN_AS_NODE=1` and a minimal env (`childEnvFor`: HOME, PATH, user and temp vars; no tokens, no NODE_OPTIONS) prints the system certificates as a JSON array of PEM strings, started with `cwd: os.tmpdir()`, killed at `SYSTEM_CERT_READ_TIMEOUT_MS` (120 s; the child costs main nothing while it waits), on a quit that goes ahead (`stopSystemCertRead` inside the one before-quit handler; the child is unref'd, so after a crashed main it can outlive it until its native call returns) or past 8 MB of output; index.ts exits at once when `ELECTRON_RUN_AS_NODE` is set in the main script (a RunAsNode fuse turned off would otherwise boot a full app in the child); non-zero exit, spawn error or malformed output fail open; main merges and sets. `systemCertTrust()` is 'pending' (darwin read running; fetches use defaults), 'applied' (store consulted, even when it adds nothing, logged at info) or 'unavailable' (reading failed, one warn). `probe.ts` `describeFetchFailure(e, host, trust)` words the certificate hint by that state ("If this network inspects HTTPS, its root certificate must be in your system's certificate store. Otherwise the server's own certificate chain may be incomplete or self-signed."; pending says try again in a moment; unavailable says OrgAI could not read the store); only chain codes get it (UNABLE_TO_GET_ISSUER_CERT_LOCALLY, UNABLE_TO_VERIFY_LEAF_SIGNATURE, SELF_SIGNED_CERT_IN_CHAIN, DEPTH_ZERO_SELF_SIGNED_CERT, CERT_UNTRUSTED), never expiry, altname or ERR_TLS_* codes. Verified by fake-spawner unit tests; on Windows with the repo's Electron 45.1.0 (Node 24.22.1) the real child script was run through the darwin path by injecting the platform: it returned 64 certificates in about 73 ms (that run, not an app boot), `setDefaultCACertificates` accepted them and the child exited 0; a hanging child was killed at an injected 1.5 s timeout. Earlier: the setter makes global `fetch` accept a local self-signed server (DEPTH_ZERO_SELF_SIGNED_CERT before, success after). The hint decides by the error code when there is one (the message regex only without a code). UNVERIFIED: the real macOS Keychain path, a packaged build, a certificate from an OS store reaching `fetch`, a real inspecting proxy, Linux, a real Electron quit. Child CLIs (Claude, Codex) are not covered by it.

  - Opt-in window placement for tests and walkthroughs (`src/main/windowPlacement.ts`, read once at startup, every window): `ORGAI_WINDOW_DISPLAY=secondary` (first non-primary display) or a 1-based number (displays ordered left-to-right, top-to-bottom) centres the window in that display's work area, unknown value or missing display logs once and falls back; `ORGAI_WINDOW_INACTIVE=1` uses `showInactive()`. `ORGAI_WINDOW_HIDDEN=1` (the local e2e default, `appEnv()` in `e2e/lib.mjs`; `scripts/verify-pack.mjs` uses it too) shows the window to Chromium at opacity 0, click-through, off the taskbar and inactive (a never-shown window has no frames: `page.screenshot` times out), see `windowShowMode` (ghost on Windows and macOS only: `setOpacity` does not exist elsewhere, so on Linux hidden keeps the old never-shown behaviour, which verify-pack's Linux boot check relies on). Both `ORGAI_WINDOW_HIDDEN` and `ORGAI_QUIET` are honoured only when `ORGAI_DATA_DIR` is also set non-empty (a persistent variable in a real install cannot hide or silence the app; one `log.info` line names the active switches), and `ORGAI_WINDOW_*` / `ORGAI_QUIET` are in `ORGAI_CONTROL_ENV_PATTERNS` so agent children never inherit them. A notification click goes through the notifier's `reveal` dep (`showWindow`), so the show mode is decided in one place. `ORGAI_QUIET=1` (set by every e2e launch, CI included; `E2E_NOTIFY=1` opts out; `src/main/quietMode.ts`) suppresses the OS notification, taskbar flash and Dock bounce at their last step, from the environment at process start only. `ORGAI_WINDOW_LARGER_THAN_SCREEN=1` (CI only, set on the macOS e2e leg in ci.yml) passes `enableLargerThanScreen: true` so the 1600x1000 / 2400x1000 e2e windows are not clamped to the runner's 1024x684 work area (macOS-only constructor option; UNVERIFIED live until the first macOS CI run). Only those exact forms count. Unit-tested: the parsing (exact '1', the ORGAI_DATA_DIR rule), `windowShowMode` per platform, the notifier's `quiet` / Dock-bounce suppression and `reveal` click path, the childEnv scrub. Only seen in local Windows e2e runs, not unit-tested: opacity 0, `setIgnoreMouseEvents`, `skipTaskbar` wiring, no window appearing or taking focus. UNVERIFIED: macOS (Electron may activate the app at launch regardless of `showInactive`; `app.dock.hide()` deliberately not added blind), and whether a skipTaskbar ghost still appears in Alt+Tab or to screen readers on Windows. A different scale factor on the second monitor can shift pixel-based e2e checks.

  - e2e selection (owner decision 2026-11-10): the check job runs `scripts/e2e-select.mjs`. Full chain (49 scripts, 34-39 min per OS before) for `workflow_dispatch`, pull requests into main (the `edited` type starts a new run when a PR is retargeted), pushes to main and `schedule` (03:17 UTC, checkout `ref: dev`; it starts only once this ci.yml is on main because scheduled workflows run from the default branch, and GitHub disables schedules on a public repo after 60 days without activity); pushes and PRs to dev run the mapped scripts plus layout, runs and cli-readonly. A push to dev is diffed (two-dot) against the head of the last successful CI push run on dev, found with `gh run list` (needs `actions: read`); no result or a non-ancestor base runs everything, which also makes cancel-in-progress harmless. PRs diff three-dot against the base. Bundled-docs-only pushes (README.md, docs/how-it-works.md, docs/design/*.md) never reach CI (`paths-ignore`), so their self-help mapping only fires on PRs. The selector escapes control characters in file names before logging, and refuses a malformed `e2e:free` chain (exit 2). The nightly run skips pack and npm (every dev push already ran them); its concurrency group is its own so it never cancels a main push run. Checked: the selector's unit tests (fail-open, shared paths, order, every chain script reachable), `--print` on real commit ranges (a Pocket Office change selected canvas plus the smoke set, 4 of 49; a NewRunPage.tsx or claude.ts change ran all 49), and ci.yml parsed with js-yaml.
