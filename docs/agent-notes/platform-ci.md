# macOS, packaging and CI

Platform notes and CI. Moved out of CLAUDE.md on 2026-11-07; see CLAUDE.md for the index.

- macOS is untested; nobody has run it on a Mac yet (`docs/macos-testing.md` is the checklist).
  - Dev app name: `predev` / `prestart` / `prepreview` run `scripts/mac-dev-app-name.mjs` (darwin only, pure argv in `scripts/lib/macDevAppName.mjs`): plutil sets the dev Electron.app's CFBundleName / CFBundleDisplayName to OrgAI, then ad-hoc codesign; never fails dev. Unit-tested with an injected runner; real Mac behaviour UNVERIFIED.
  - App icon: `npm run icon` (`scripts/make-icon.mjs`, pure parts in `scripts/lib/icon.mjs`, tested in `src/main/icon/makeIcon.test.ts`) writes `build/icon.png` (1024), `build/icon.ico` (16-256, Windows) and `build/icon.icns` (macOS, mark inset to ~80% with a transparent margin); commit all three together. In dev, `index.ts` sets the window icon (ico on Windows, png elsewhere) and on darwin `app.dock.setIcon` (never packaged). Verified by unit tests and file inspection; the Dock, Finder and taskbar rendering is unverified on a Mac.
  - `trustSystemCertificates(options?)` (`src/main/systemCerts.ts`, issue #16) runs after `applyShellPath()`, only once the single-instance lock is ours (a second launch that exits never starts the macOS reader), and the in-process `orgai` (`src/cli/inprocHost.ts`, option `systemCertificates`, default on) calls it right after taking `<data>/run/` ownership and stops the read when the host ends or the process exits (unit-tested with injected hooks; the real CLI path is unverified): `tls.setDefaultCACertificates` gets the defaults plus the OS store's certificates (deduplicated, fail-open) so main-process `fetch` trusts a corporate / inspecting root CA. Windows and Linux read the store synchronously. macOS never reads it on the main thread, except in launches with `--use-system-ca` where `getCACertificates('default')` reads the store (`getCACertificates('system')` can stall in the Security framework, nodejs/node#63313; public reports of 5 s to about 10 s, one of 107 s, anthropics/claude-code#76079): a child `process.execPath -e <script>` with `ELECTRON_RUN_AS_NODE=1` and a minimal env (`childEnvFor`: HOME, PATH, user and temp vars; no tokens, no NODE_OPTIONS) prints the system certificates as a JSON array of PEM strings, started with `cwd: os.tmpdir()`, killed at `SYSTEM_CERT_READ_TIMEOUT_MS` (120 s; the child costs main nothing while it waits), on a quit that goes ahead (`stopSystemCertRead` inside the one before-quit handler; the child is unref'd, so after a crashed main it can outlive it until its native call returns) or past 8 MB of output; index.ts exits at once when `ELECTRON_RUN_AS_NODE` is set in the main script (a RunAsNode fuse turned off would otherwise boot a full app in the child); non-zero exit, spawn error or malformed output fail open; main merges and sets. `systemCertTrust()` is 'pending' (darwin read running; fetches use defaults), 'applied' (store consulted, even when it adds nothing, logged at info) or 'unavailable' (reading failed, one warn). `probe.ts` `describeFetchFailure(e, host, trust)` words the certificate hint by that state ("If this network inspects HTTPS, its root certificate must be in your system's certificate store. Otherwise the server's own certificate chain may be incomplete or self-signed."; pending says try again in a moment; unavailable says OrgAI could not read the store); only chain codes get it (UNABLE_TO_GET_ISSUER_CERT_LOCALLY, UNABLE_TO_VERIFY_LEAF_SIGNATURE, SELF_SIGNED_CERT_IN_CHAIN, DEPTH_ZERO_SELF_SIGNED_CERT, CERT_UNTRUSTED), never expiry, altname or ERR_TLS_* codes. Verified by fake-spawner unit tests; on Windows with the repo's Electron 45.1.0 (Node 24.22.1) the real child script was run through the darwin path by injecting the platform: it returned 64 certificates in about 73 ms (that run, not an app boot), `setDefaultCACertificates` accepted them and the child exited 0; a hanging child was killed at an injected 1.5 s timeout. Earlier: the setter makes global `fetch` accept a local self-signed server (DEPTH_ZERO_SELF_SIGNED_CERT before, success after). The hint decides by the error code when there is one (the message regex only without a code). UNVERIFIED: the real macOS Keychain path, a packaged build, a certificate from an OS store reaching `fetch`, a real inspecting proxy, Linux, a real Electron quit. Child CLIs (Claude, Codex) are not covered by it.
  - `applyShellPath()` runs right after `installLogging()` and merges the login shell's PATH with well-known dirs.
    GUI launches otherwise miss Homebrew, nvm and similar.
  - The well-known `claude` folders (`~/.claude/local/claude`, `~/.local/bin/claude`, `/opt/homebrew/bin/claude`,
    `/usr/local/bin/claude`; `claudeWellKnownPaths`) are only named in an error since Wave 7, never run.
  - The app menu is installed on darwin only. Closing the window keeps the app running, and `activate` re-creates
    the window.
  - These pieces are unit-tested where they are pure. Packaging (`dist:mac`, `dist:mac:unsigned`,
    `build/entitlements.mac.plist`) is unverified.
  - Opt-in window placement for tests and walkthroughs (`src/main/windowPlacement.ts`, read once at startup, every window): `ORGAI_WINDOW_DISPLAY=secondary` (first non-primary display) or a 1-based number (displays ordered left-to-right, top-to-bottom) centres the window in that display's work area, unknown value or missing display logs once and falls back; `ORGAI_WINDOW_INACTIVE=1` uses `showInactive()`. `ORGAI_WINDOW_LARGER_THAN_SCREEN=1` (CI only, set on the macOS e2e leg in ci.yml) passes `enableLargerThanScreen: true` so the 1600x1000 / 2400x1000 e2e windows are not clamped to the runner's 1024x684 work area (macOS-only constructor option; UNVERIFIED live until the first macOS CI run). Only those exact forms count. Unit-tested; a different scale factor on the second monitor can shift pixel-based e2e checks.
  - `ORGAI_DATA_DIR` replaces userData and puts the logs under it. e2e (a fresh temp dir per script) and CI use it to
    keep off the real profile. Since 18070b8 the e2e scripts ignore an ambient `ORGAI_DATA_DIR` (`E2E_DATA_DIR` is the
    override): CI's one shared dir let connections.mjs's leftover library entry open a different dialog in team.mjs.
    package.json `productName: "OrgAI"` names the packaged app (`app.name`, log dir).
  - The `pathKey` symlink fix (macOS `/tmp` is `/private/tmp`) and the OrgAI identity fallback for commit and merge are
    unit-tested with a junction/symlink and a git that has no identity config.
  - CI (`.github/workflows/ci.yml`) runs on windows-latest and macos-15. Release legs run on native-arch runners
    (macos-15 arm64, macos-15-intel x64). macos-14 was refused from 2026-11-05 (jobs cancelled with "The configuration
    'macos-14-arm64-us-default' is not supported"; the same jobs passed at 18:25 UTC that day), so CI and release moved
    to macos-15 (unrun: the first macos-15 CI run has not happened). Nothing in CI spends tokens. A push that changes only `docs/**` or Markdown
    files does not trigger it (`paths-ignore`); pull requests always run.
  - e2e selection (owner decision 2026-11-10): the check job runs `scripts/e2e-select.mjs`. Full chain (49 scripts, 34-39 min per OS before) for `workflow_dispatch`, pull requests into main (the `edited` type starts a new run when a PR is retargeted), pushes to main and `schedule` (03:17 UTC, checkout `ref: dev`; it starts only once this ci.yml is on main because scheduled workflows run from the default branch, and GitHub disables schedules on a public repo after 60 days without activity); pushes and PRs to dev run the mapped scripts plus layout, runs and cli-readonly. A push to dev is diffed (two-dot) against the head of the last successful CI push run on dev, found with `gh run list` (needs `actions: read`); no result or a non-ancestor base runs everything, which also makes cancel-in-progress harmless. PRs diff three-dot against the base. Bundled-docs-only pushes (README.md, docs/how-it-works.md, docs/design/*.md) never reach CI (`paths-ignore`), so their self-help mapping only fires on PRs. The selector escapes control characters in file names before logging, and refuses a malformed `e2e:free` chain (exit 2). The nightly run skips pack and npm (every dev push already ran them); its concurrency group is its own so it never cancels a main push run. Checked: the selector's unit tests (fail-open, shared paths, order, every chain script reachable), `--print` on real commit ranges (a Pocket Office change selected canvas plus the smoke set, 4 of 49; a NewRunPage.tsx or claude.ts change ran all 49), and ci.yml parsed with js-yaml. Unverified: the live Actions behaviour (history fetch with `fetch-depth: 0`, the pull request merge-ref diff, the `gh run list` lookup and its token permission, ancestor check after a force push falling back to full) until the first push.
  - `e2e-select.mjs --run` runs every selected script even after a failure (a script has a 10 min limit, `E2E_SCRIPT_TIMEOUT_MS`), prints a summary listing each failed script and exits 1 if any failed (2026-11-13; before, the first red script hid every script behind it; unrun on macOS until the next CI run).
  - The first real CI run has not happened yet. Open items: winCodeSign extraction on windows-latest, macos-15-intel
    really being x64, e2e:free on mac (a possible Keychain prompt), unsigned dmg/zip with hardenedRuntime, the publish job.
  - `store/runs.ts` renames (index, record, image temp files) go through `renameSyncRetry` (host/fsRetry.ts) so a transient Windows EPERM/EBUSY/EACCES on `runs.json.tmp` -> `runs.json` no longer fails an `orgai exec` run (e2e/separation.mjs flaked red on windows-latest 26d756f6, 1 of 2 locally). Checked: runs.test.ts asserts the store uses the helper; 6 local separation runs green. The race itself was not reproduced deterministically; CI is the real check (2026-11-13).
